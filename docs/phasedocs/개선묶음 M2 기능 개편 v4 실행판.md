## 4. 규약 (구현으로 확정된 것 — 되돌리면 깨지는 것들)

### 4-A. 다이얼로그
- **네이티브 `alert`/`confirm`/`prompt` 직접 호출 금지** → `lib/dialogs.ts` 경유.
- `lib/dialogs.ts`는 **import 0**이다(다른 순수 모듈 관례) → `npm run test:dialogs`가 단독 컴파일한다.
  훅이 아니라 **모듈 싱글턴**인 이유: 호출부가 React 밖에도 있다(`lib/pdfPrint.tsx`).
- **큐 필수** — 겹쳐 띄우면 오버레이가 두 겹이 되고 Escape가 어느 것을 닫는지 알 수 없다.
- **Host 부재·언마운트 시 대기 요청을 기본값으로 흘려보낼 것** — 안 하면 호출부가 영원히 `await`한다.
- 스타일은 `dialogStyles.ts` 하나가 소유하고 **SheetImportModal 값을 복제**했다(radius 10 · 테두리 없음).
  ⚠ 새 규격을 만들지 말 것 — 목적은 "팝업이 두 갈래로 갈린 것"을 없애는 것이지 아홉 번째 모달 디자인이 아니다.
- `Z_DIALOG = 10500`(현행 최고 10000 위). 기존 z-index 재배치는 범위 밖.
- ⚠ **문항 이동 픽커 ≠ 폴더 재부모화**. 문항엔 자손이 없으므로 **순환 방지가 필요 없다**
  (v1이 이 둘을 섞어 적었다). 요건은 ① 동명 폴더 계층 구분 ② '미지정' 선택 ③ 휴지통 제외.
- `components/print/PdfDownloadButton.tsx`는 **import 0인 죽은 파일**이라 치환에서 제외했다(별건 삭제 후보).

### 4-B. 선택지 정렬
- `center`가 통하는 이유는 **그리드 아이템의 기본 `align-items: stretch`** 다 — 5개 셀 높이가 이미 같아서
  center가 라벨을 정확히 같은 y에 놓는다. 실측: baseline 편차 9.33/12.81/20.91px(11·15·24px) → center **0.00px**.
- ⚠ 그리드↔래퍼 구조(`display:contents`·서브그리드)를 바꾸지 말 것 — stretch가 깨지면 근거가 사라진다.
- `.print-choice-item`에 `.print-body` 접두를 붙이지 말 것(그 클래스는 인쇄 전용이라 누출이 없다).

### 4-C. 참조 인용 말풍선
- 마크업은 `lib/locale.ts`가 소유한다. 정규식 상수는 **`/g` 없이** 정의하고 호출부가 인스턴스를 만든다(파일 규약).
- **보호 목록에 `ref-marker` 자신이 들어가야 한다** — 없으면 2회째 실행에서 여닫는 태그만 낱개로 빠지고
  내부 `①`이 노출돼 재감쌈된다(멱등성 파괴). 돌연변이 시험으로 확인: 빼면 `M2-C6`만 정확히 깨진다.
- marker 계열을 **요소 통째로** 보호하지 않으면 **정의부가 참조로 둔갑**한다(프로토타입 실측 5건).
- 자모 경계는 **뒤쪽 lookahead에서 한글 음절을 배제하지 않는다** — 배제하면 `ㄱ이`·`ㄱ은`·`ㄷ에서`·`ㄴ의`를
  전부 놓친다(표본 7개 중 4개). 앞쪽만 막으면 ㄲ·ㄸ·ㅃ·ㅆ·ㅉ·ㅋㅋ·모음 오탐이 0이다.
  ⚠ **범위 표기 `[ㄱ-ㅊ]` 금지** — 겹자모가 그 안에 들어온다.
- 비교는 `normalizeRefText`(trim → 공백·`$` 제거 → 꼬리 `.` 1개 제거). 안 하면 `ㄱ.`↔`ㄱ`, `C1.`↔`C1`이
  영원히 매칭되지 않는다.
- 게이트(`data-ref-tooltip`)는 **탭 전체를 감싸는 컨테이너**에 붙인다 — 탭 하나에 붙이면
  "문제 탭에서 정의하고 풀이 탭에서 인용"이라는 지배적 사용이 통째로 안 잡힌다.
- 말풍선 안은 `.preview-content tone-baseline`으로 감싸고 `--content-font-size`를 복사한다.
  안 하면 본문 24px에서 번호가 폴백 15px로 떨어진다(실측). **복제 단위는 `.katex-display` 이상.**
- **React 상태 0** — 프리뷰에 상태가 생기면 리렌더가 innerHTML을 다시 써서 드래그 선택이 죽는다.
- ⚠⚠ **정의부를 언마운트하는 기능을 만들지 말 것.** 보기의 정의부는 **문제 탭에 살고** 참조는 풀이에 있다.
  접힘·요약이 문제 탭 내용을 DOM에서 지우면 풀이의 참조가 **한꺼번에 무음**이 된다(실제로 그랬다 — `5c242b3`).
  숨겨야 하면 `visibility:hidden`(+`position:absolute`)으로 **노드를 남길 것**.

### 4-D. ProblemView
- **컨테이너는 block이어야 한다.** flex는 두 가지를 동시에 깬다:
  ① `justify-content:center`의 좌측 넘침은 **스크롤 영역에 포함되지 않아** `overflow-x:auto`로도 닿을 수 없다
     (실측: 자식 780인데 `scrollWidth` 690) ② 기본 `align-items:stretch`가 자식 높이를 눌러 **sticky가 죽는다**
     (실측: 300px 스크롤 후 −220px). 자식 폭은 `fit-content`가 아니라 **`max-content`** (전자는 유동 폭에서 조용히 클램프).
- **하단 스페이서(70vh)는 자동접힘의 전제다.** 제목행 접힘은 scrollTop이 아니라 clientHeight를 키우므로,
  스크롤 여유가 없으면 브라우저가 scrollTop을 클램프해 임계값 밑으로 떨어뜨리고 진동이 반복된다.
- **접힘 시 scrollTop 보정은 T1 아래로 내리지 않는다** — 그대로 보정하면 임계값 밑으로 떨어져 다시 펼쳐진다.
- sticky 문제 행의 **래퍼가 아이보리를 칠해야 한다** — 안 칠하면 스크롤된 풀이 카드가 여백을 통과하며 비친다.
- 카드에 **`overflow:hidden` 금지**(경우 rail이 좌측 거터 −1.8em에 그려진다). 좌 패딩 40px이 그 자리를 준다.
- 제목행 gap은 `LABEL_GAP_EM × contentFontSize`로 TabBody와 **한 상수를 공유**한다(고정 px 금지).
- `widthEm`은 **제목행 `<h1>`과 TabBody 두 사본 모두**에 적용한다 — 제목·카드 우단이 함께 움직여야 좌단 정렬이 성립.
- ⚠ **컨텐츠 행에 `position:relative`를 주지 말 것**(Phase 62 규약) — 절대배치 컨트롤이 제목바 높이만큼 내려간다.
- `M2_COLLAPSE = { T1: 80, T2: 8, DELAY_MS: 300, COOLDOWN_MS: 400 }`. 튜닝 허용 범위 T1 60~120 · DELAY 200~500 · COOLDOWN 300~600.

### 4-E. 3단 구분 (좌 < 중 < 우)
- **밝기 서열이 3단 구분의 전부다.** 상대휘도 실측: 사이드바 `#FAF7F2` 0.9326 < 중앙 `#FCFAF6` 0.9572 < 드로어 `#FFFFFF` 1.0000.
  ⚠ 중앙을 더 낮추지 말 것 — `#FBF8F3`(0.9412)이면 사이드바와의 차가 0.009로 줄어 구분이 사실상 사라진다.
- 세 색 모두 아이보리 계열이라 **명암비 최악값(FolderView 카드 hover `#E8DFCE`)은 불변** — Phase 58·59a 계산 유효.
- 우측 패널 4종(우측 단·댓글·agent·버전)은 **떠 있는 카드**다: `DRAWER_INSET 8` 사면 여백 · `DRAWER_RADIUS 10` ·
  `DRAWER_BORDER 1px --border-content` · 2겹 그림자. 한 변이라도 0이면 "붙어 있는 패널"로 읽힌다.
- **`DRAWER_ROW1_H = 57 − DRAWER_INSET − DRAWER_BORDER_W`(=48)** — 중앙 컨텐츠의 두 가로선(y=57·98)과 정렬하기 위한 값.
  ⚠ 48을 숫자로 굳히지 말 것(inset·테두리를 바꾸면 자동으로 따라온다). ⚠ 2행(41)은 건드리지 말 것(두 선의 간격이다).
- **컨텐츠 예약 폭의 정의는 "드로어 카드의 좌측 경계선까지"** 다. 그보다 크면 그 차이만큼 빈 띠가 생겨
  컨텐츠가 잘려 나간 것처럼 보인다. 두 경우의 식이 다르다 — 댓글·agent `width + 8`, 우측 단 `width − 8`.
- 패널 폭은 `PANEL_WIDTH_DEFAULT = 420` 하나를 4곳이 공유한다(구 220/460/420) — 갈리면 패널을 오갈 때 본문 폭이 계단처럼 튄다.
- 페이드·그라디언트 색은 **토큰을 그대로** 쓴다(하드코딩 rgba 금지) — 바탕색을 바꿨을 때 페이드만 옛 색으로 남던 사고가 있었다(`78a780f`).

### 4-G. 코칭블록
- 종류는 **'Tip' 하나**다. `coachClassName`은 타입 무관 `coach-block coach-important`를 낸다.
  Phase 59a v4 Q2("영문 어절 유지")를 번복한 이유: 종류가 1개면 Important↔Caution 대비가 사라져 GitHub 어휘 체계 자체가 소멸한다.
- 레거시 `coach_caution`은 **`normalizeBlockType` 1줄**로 흡수한다(`math_block`·`bullet` 전례). 배치 마이그레이션 0.
- ⚠ `BLOCK_TYPES`에서**만** 뺀다 — `BLOCK_PRESETS`·`TEXT_BASED_TYPES`·`SPLITTABLE_TYPES`·`BLOCK_TYPE_LABELS`와
  `solutionOutline.ts:74`에는 남겨야 정규화 이전에 로드된 블록의 편집·분할·요약이 죽지 않는다.
- `CoachBlock`은 본문을 **children으로 받는다** — 인쇄만 `PrintBlockRenderer`를 쓰므로, 껍데기가 본문 렌더러까지
  소유하면 인쇄가 이 컴포넌트를 못 쓰고 접힘 규약이 다시 사이트별 사본으로 갈린다.
- 폴더뷰 카드는 **항상 펼침** — 320px 축약 카드에서 아이콘 하나만 남으면 무엇이 들었는지 알 수 없다.
