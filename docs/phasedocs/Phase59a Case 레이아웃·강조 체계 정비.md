## 0. 최종 사양

### 0-1. 강조의 네 축

| 축 | 수단 | 하는 일 |
|---|---|---|
| 위치 | `callout` 블록 (UI 이름 **'들여쓰기'**) | 좌단을 독립행 수식 자리로. 색 불변 |
| 색·굵기 | 인라인 `**…**` | 그 구간만 primary + 600 |
| 신호 | `coach_important` · `coach_caution` | 색 바 + 아이콘 + 라벨 |
| 요약 구성 | '요약에 넣기' 스위치 | 그 블록이 요약 보기에 남는다 |

**'강조'는 이제 `**` 하나만 가리킨다.** 레이아웃 장치에 그 낱말을 다시 붙이지 말 것.

### 0-2. 좌표 (거터 체계)

x = 0 이 본문 좌단. 음수가 본문 바깥.

```css
--case-rail-x:    -1.8em;   /* rail·dot 중심 */
--case-chevron-x: -0.7em;   /* 요약 보기 chevron glyph 중심 */
```

| 대상 | 값 | 비고 |
|---|---|---|
| rail · dot | -1.8em | 인쇄는 -1.2em (단 간격 10mm 제약) |
| 경우 줄 chevron | 중심 -0.7em | 제목 줄과 같은 열 |
| 경우·하위 경우 본문 | **0** | 일반 텍스트와 동일 |
| 개재 블록(case-gap) | **0** | 타입 불문 |
| 경우 안 수식·리스트·① | 최상위 규칙 승계 | override 0 |

**필요 거터 폭 = 2.06em(실사용 2.2em).** 각 사이트가 `overflow:hidden` 경계 **안쪽**에 확보한다:
ProblemView `LABEL_GAP = 2.8 × contentFontSize` · EditorView 미리보기 `paddingLeft: 3.5em` ·
공유 ContentCard 좌측 40px · **FolderView 카드는 rail·dot 미표시**(§0-5).

### 0-3. 톤

풀이·추가 탭(`tabId !== 'question'`)은 **조건 없이 항상** dim(`--tone-dim #675F52`)이고
`**` 구간만 primary + 600으로 나온다. Phase 58의 D4(opt-in)는 폐기.
제목·경우 제목행은 톤 불변(구조 신호). 인쇄는 100% 복원 + `**`만 700.

### 0-4. 요약 보기

남는 것은 **정확히 셋** — 제목 블록 · 경우/하위 경우 제목행 · `showInSummary`를 켠 블록.
`**` 발췌는 폐기. 제목 블록과 경우 계열에는 스위치를 두지 않는다(자동 포함이라 할 일이 없다).

**경우 제목행을 누르면 '구역'이 열린다**: 구역 = 그 경우 + 다음 **제목행 있는** 경우 직전까지.
제목 블록에서 끊기고, **이어짓기는 경계가 아니다**(직전 경우의 연속). 접힘 = `pinned` /
펼침 = `segment` **배타 렌더**(동시에 그리면 같은 블록이 두 번 나온다).

### 0-5. 코칭 블록

`coach_important` · `coach_caution`. 라벨(Important/Caution)은 raw_text가 아니라 렌더가 붙인다.
`lib/coachBlock.ts` + `components/ui/CoachLabel.tsx`를 5사이트가 공유.
색 `#6639ba` / `#a40e26` (GitHub light 기본값은 카드 배경에서 4.5:1 미달 → 700 계열로 승격).
상자 안쪽 패딩 1em은 **들여쓰기가 아니라 상자의 내부 여백**(글상자 3종의 전례).

## 2. 실측 검증

### 2-1. 좌표 (headless Chrome · globals.css 직접 로드)

| 항목 | 11px | 15px | 24px |

| dot 좌단 / 우단 | -2.06 / -1.54 | 동일 | 동일 |

헤어라인 보정**이다(레티나 1물리픽셀 중심 맞춤). 그 외 전 항목 비례.
인쇄: 침범 5.01mm / 단 간격 10mm 중 잔여 4.99mm.

### 2-2. 톤 — 변경 전 커밋 CSS와 나란히 대조

`fdeac85`의 globals.css·PrintStyles.css를 꺼내 같은 DOM에 물려 비교.

- **`**`가 있는 문항: 11개 항목 픽셀 완전 동일** (강조 안 수식·제목 안 수식·경우 제목행 수식·
  인쇄 복원·굵기 전부). v2의 doubling 처방이었다면 앞의 둘이 dim으로 죽었을 자리다.
- **`**`가 없는 문항(의도된 변화)**: 본문 글자 `#5D5647 → #675F52`(소폭),
  **본문 수식 `#2D2A23 → #675F52`(대폭)**. 제목은 글자·수식 모두 무변화(D9′ 가드 작동).
- **레거시 `**Case n.**` 문항: 6개 항목 전부 동일** + 요약 승격 유지.

⚠ **인쇄에서 경우 제목행 안 수식만 `#000`이 아니라 `#2D2A23`으로 나온다.** 케이스 가드(0,5,1)가
인쇄 복원(0,3,0)을 이기기 때문이며 **변경 전에도 (0,6,1) vs (0,4,0)으로 같았던 기존 동작**이다.
육안 구별이 안 된다 — 회귀로 오인하지 말 것.

### 2-3. 구역 펼침 시 rail 연속성
