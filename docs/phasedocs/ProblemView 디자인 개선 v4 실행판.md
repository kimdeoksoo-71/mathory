## 1. 설계 기준 — 이 작업이 답한 질문

덕수가 실사용에서 내린 판정이 방향을 결정했다.

> "체감하는 중요한 문제점은 **시각적 안정감이 줄어들어 보인다**는 것.
>  스크롤할 때 문제 카드가 사라지고 나타나는 순간 **화면이 튄다**는 느낌이 있어."
>
> "제목행 자동 접힘 버림은 의도적인 거야. 처음엔 신기해 보여서 좋았는데, 막상
>  반복 사용하다 보니 **시각적 피로감**이 느껴져. Mathory는 **안정감 있고 빈틈없이
>  보수적으로 작동하는 수학 글쓰기 도구**여야 해."

v1·v2(양쪽)는 "스크롤하면 카드를 숨긴다"를 전제로 그때 생기는 튐을 **보정하는** 설계였다.
v3·v4는 방향을 뒤집었다 — **튈 일을 만들지 않는다.**

그 전환으로 사라진 것: 숨김 임계값 · `scrollTop` 보정 · 복원 스크롤 · 반복 숨김 정책 ·
`questionShown`/`hiddenOnce`/`scrolled`/`headerSlim`/`questionCollapsed` 상태 ·
진동 방지 쿨다운 · 접힘 높이 델타 보정 · 왕복 시 읽던 자리 상실 ·
그리고 **참조 말풍선 회귀 위험(M2에서 가장 값비쌌던 사고)이 원천 소멸**했다.

> **최종 코드에 `scrollTop`을 읽거나 쓰는 곳이 하나도 없다.** 판정은 rect 비교뿐이다.
> 남은 상태는 `problemOffscreen`·`peeking` 둘이고 **둘 다 레이아웃에 영향이 없다** →
> 진동이 구조적으로 불가능하다.

## 3. 계획을 뒤집은 것 (R1~R7) — 옛 결정 번호를 인용하기 전에 볼 것

| # | 계획 | 확정 | 이유 |
|---|---|---|---|
| **R1** | v1·v2 P절: 스크롤하면 카드를 **숨기고** 튐을 보정 | **숨기지 않는다** + hold-to-peek | 덕수 실사용 판정("화면이 튄다"). 보정 대신 원인 제거 — §1의 목록이 통째로 사라졌다 |
| **R2** | 메모 항목 2 + web v2 Q절: 스크롤 시 풀이 카드 위 **가로선 + 페이드** 등장 | **Q절 전면 폐기**, 제목행 상시 `borderBottom` 1줄로 대체 | 선·페이드는 **sticky 카드 전용 처방**이었다("카드가 선 밑으로 밀려 들어간다"). R1로 sticky를 떼면서 밀려 들어갈 대상이 없어졌다. ⚠ 이 폐기가 v3 내부 모순도 정리했다 — Q절은 `scrolled` 상태를 쓰는데 상태 기계에는 2개만 적혀 있었다 |
| **R3** | 알약을 **제목 바로 오른쪽**(v3 초안) → **제목행 우측 끝**(1차 수정) | **좌측 라벨 거터, 풀이 라벨 바로 위** | 덕수: "그게 더 직관적이야". 실측으로 근거가 드러났다 — **문제 탭 라벨은 sticky가 아니고 풀이 탭만 sticky**라, 그 바로 위는 방금 `문제` 라벨이 밀려 올라간 자리다. 게다가 sticky 안 `absolute`라 **흐름 기여 0** → '자리 예약'(R7)도 불필요해졌다 |
| **R4** | 알약 라벨 **'문제 보기'**(V5′) | **'문제'** | 라벨 열 폭이 `7 × contentFontSize`라 11px에서 **77px**인데 알약 글자는 고정 12px이라 '문제 보기'는 ~80px로 넘친다. 실측 '문제' = **40.8px**. 게다가 거터에서 `[문제] / 풀이`로 읽혀 자리의 의미가 산다 |
| **R5** | v1·v2·v3 S1: **경우 줄 chevron만** 제거 | **노브 전부**(제목 줄 포함) | ⚠ **계획서가 원본 메모를 좁힌 것**이다. 덕수 메모 원문은 한정 없이 *"현재의 노브는 없앤다. 간결함을 저해하는 요소로 작용되고 배경톤 진해짐 효과와 기능 중복"*이고 절 제목이 `요약보기에서 펼침, 접힘`이다. CLI v1이 "rail을 막는 것은 경우 줄뿐"(B-5)이라는 판단을 **제거 대상과 뒤섞어** 좁혔고, web v2·v3가 검증 없이 승계해 v3 §7에서는 "제목 줄까지 없애지 말 것"이라는 **금지 조항**이 됐다. 덕수 검수에서 발견 |
| **R6** | 제목행 `height: 98`(web R-11) | **`height: 57`** | 덕수: "1행 아래 빈 2행은 공간 낭비". 98은 EditorView Row1+Row2 **두 행치**인데 ProblemView는 1행 내용만 담아 ~50px이 비었다("추후 메타데이터"용 예약이 끝내 안 왔다). 57은 앱 전역 1행 높이 |
| **R7** | 알약 **자리 예약**(`visibility` 토글, 마운트 금지) | **불필요** | R3의 `absolute`가 흐름 기여를 0으로 만들어 예약할 자리 자체가 없다. `opacity`로 여닫는다 |

### R5·R6이 남긴 교훈

둘 다 **계획서가 원본을 잃어버린** 사례다. R5는 세 판을 지나는 동안 아무도 덕수 메모와
대조하지 않았고, R6은 코드 주석("추후 메타데이터")이 이유를 밝혀 뒀는데도 계획서가
그 예약을 사실로 굳혔다. → **판을 거듭할수록 원본 메모와의 대조를 한 번은 다시 할 것.**

## 4. 확정 규약 (CLAUDE.md 반영분)

- **ProblemView는 스크롤로 레이아웃이 변하지 않는다** — 카드를 숨기거나 고정하거나
  제목행을 접는 처리를 다시 넣지 말 것. v3의 값 전부가 여기서 나온다.
- **hold-to-peek에는 `setPointerCapture`가 필수다** — 없으면 누른 채 알약 밖으로
  나가서 뗐을 때 `pointerup`이 안 와 **카드가 안 닫힌다**. `pointercancel`·`blur`도 닫을 것.
  `keydown`은 길게 누르면 **반복 발화**하므로 이미 열려 있으면 무시.
- **중앙에 띄우는 카드는 `[data-ref-tooltip]` 밖에 그릴 것** — 안이면 보기의 정의부가
  두 벌이 되어 "참조보다 앞선 것 중 가장 가까운 것"이라는 탐색이 흔들린다.
- **peek 오버레이는 컨테이너 `pointerEvents:none` + 카드만 `auto`** — 둘 다 none이면
  긴 문제를 hold 중에 휠로 넘길 수 없고, 둘 다 auto면 뒤 컨텐츠를 막는다.
- **알약은 탭(TabBody) 안이 아니라 탭 전체의 첫 형제여야 한다** — 탭 안에 두면 아래
  탭으로 스크롤할 때 함께 사라진다.
- **거터는 이제 카드 안에 있다** — 카드 패딩 2.6em이 dot 좌단 1.56em을 품고 1.04em이 남는다.
  `LABEL_GAP`은 rail 통로가 아니라 순수한 시각 간격이다.
- **`--case-dot-fill`은 배경을 바꾸는 모든 스코프에서 재정의할 것** — 카드(TabBody ·
  ProblemTabContent)와 펼친 요약 섹션. 빠뜨리면 dot 안쪽만 더 밝은 구멍이 된다.
- **요약 톤은 반드시 조상 배경으로** — 자손(`.case-block::before`)이 위에 그려지므로
  rail·dot이 덮이지 않는다(실측 확인). **형제 오버레이로 만들면 그때는 덮인다.**
- **`.outline-section`의 좌우 음수 마진·패딩은 열림과 무관하게 상시** — `is-open`에만
  주면 닫힌 섹션의 여닫이 줄이 전폭이 될 수 없고 여닫을 때 좌우가 미세하게 움직인다.
- **여닫이 노브를 되살리지 말 것** — 톤과 dot이 같은 말을 이미 한다. 경우 줄에서는
  rail이 R2로 당겨 온 자리를 도로 빼앗는다. 여닫이라는 사실은 `role="button"` +
  `aria-expanded`가 나른다.
- **제목행 높이 57은 앱 전역 1행 높이다** — `dialogHead`·`BatchVerifyDialog`·
  EditorView Row1·`DRAWER_ROW1_H`(= 57 − 8 − 1). 이제 중앙 제목행 선과 **우측 단 1행
  선이 같은 Y**에 선다(옛 98은 드로어의 *둘째* 선과 맞던 어긋난 대응이었다).

## 5. 실측 기록 (CDP · 임시 라우트 `app/dev-v3`, 계측 후 삭제)

### F1 — 잠복 버그가 실재했고 고쳐졌다

카드 패딩만 px 고정이고 rail 좌표는 em이라, **글꼴을 키울수록 rail이 카드 밖으로 걸어 나갔다.**

| 글꼴 | rail (카드 좌단 기준) | | dot 좌단 | |
|---|---|---|---|---|
| | 옛(pad 40px · rail −1.8em) | **새** | 옛 | **새** |
| 11px | 20.2 | **15.3** (1.39em) | 14.0 | **12.4** |
| 15px | 13.0 | **20.5** (1.37em) | 9.1 | **16.6** |
| 24px | **−3.2** ← 카드 밖 | **32.2** (1.34em) | **−9.4** | **26.0** |

### 톤 · 알약

- 펼친 섹션 배경 `rgb(240,234,224)` = `--block-bg` ✓ / 닫힘 `transparent` ✓
- `--case-dot-fill` 펼침 `#F0EAE0`(재정의 ✓) · 닫힘 `#F4EFE7`
- ⚠ **rail 색이 세 조건 전부 `rgb(201,196,186)` 불변** → 톤이 rail을 덮지 않는다(S7 확정)
- 섹션·여닫이 줄 모두 카드 전폭(좌우 1px = 테두리 0.5 반올림)
- 알약 **높이 정확히 22px** → top 12 / bottom 34, 라벨 top 40 → **여유 6px**(P5-1 산식 일치)
- 알약 폭 **40.8px** < 라벨 열 77px(11px 글꼴) — '문제 보기'였다면 넘쳤다

## 7. 남은 후속

- hold가 "한 문장 확인"에 충분한지. 부족하면 고정 모드를 얹는다(지금은 넣지 않는다)

- M2 후속 잔여: 글꼴·폭 조절 접근성 · EditorView Row1 우측 가림 ·
  `PdfDownloadButton` 죽은 파일 삭제 · 기존 모달 8종을 `dialogStyles`로 이관 · 모바일
