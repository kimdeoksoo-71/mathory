# Phase 38: 공유 및 공개 시스템

> **목표**: 문제(folder)의 4단계 공개 등급 도입 + Team 시스템 + Plaza(공개 게시) 라우트 신설
> **상태**: 골격 (Phase 37 완료 후 본 설계 회의 예정)
> **선행 조건**: Phase 37 완료 (AI 토론 기능)
> **연계**: Phase 37의 공개토론 세션 자동 생성, AI 활성 게이트가 이 Phase에서 실제로 켜짐

---

## 1. 4단계 공개 등급 (확정)

| # | 등급 | 사이드바 위치 | 접근 권한 | AI 토론 |
|---|------|---------------|-----------|---------|
| 1 | **비공개** | **My** 카테고리 | 소유자만 (열람·편집) | ✅ 가능 |
| 2 | **Team 공유** | **Team** 카테고리(팀별) | 팀원: 열람·댓글, 권한 부여 팀원만 편집 | ✅ 가능 |
| 3-1 | **웹 공개** | **Plaza** 카테고리 → 웹 공개 폴더 | 비로그인 포함 누구나 열람·댓글 | ❌ 불가 |
| 3-2 | **회원 공개** | **Plaza** 카테고리 → 회원 공개 폴더 | 로그인 회원만 열람·댓글 | ❌ 불가 |

**AI 토론 비활성 이유**: 공개 문제에서 AI를 자유롭게 호출하면 비용이 폭주하고 어뷰징 위험. Phase 35 이후 별도 정책(쿼터/유료) 도입 시 재검토.

## 2. 데이터 모델 (개요)

### 2.1 Folder 확장

```typescript
// types/problem.ts
export interface Folder {
  id: string;
  name: string;
  user_id: string;
  order: number;
  // 🆕 Phase 38
  category: 'my' | 'team' | 'public_web' | 'public_member';
  teamId?: string;              // category === 'team'일 때 필수
}
```

### 2.2 Team 컬렉션 (신규)

```typescript
// Firestore: teams/{teamId}
export interface Team {
  id: string;
  name: string;
  ownerUid: string;             // 팀장 (1명)
  memberUids: string[];         // 일반 팀원
  editorUids: string[];         // 편집 권한이 부여된 팀원 (memberUids의 부분집합)
  createdAt: Date;
  updatedAt: Date;
}
```

### 2.3 Problem 가시성

- 문제의 가시성은 **소속 folder의 category에서 상속**. problems 컬렉션에 명시 필드 없음 (단일 출처 원칙).
- 폴더 이동 시 가시성도 함께 변경됨.
- Phase 37의 AI 토론 가능 여부 검사: `folder.category === 'my' || folder.category === 'team'`

## 3. 사이드바 정보 아키텍처

```
[Sidebar]
├── 🔒 My (비공개)
│   ├── 폴더 A
│   └── 폴더 B
├── 👥 Team
│   ├── 팀 ①  [팀 설정 ⚙]
│   │   └── 폴더 …
│   ├── 팀 ②
│   └── [+ 새 팀 만들기]
└── 🌐 Plaza (공개)
    ├── 🌍 웹 공개 폴더
    └── 🔐 회원 공개 폴더
```

- 비로그인 사용자: My/Team 숨김, Plaza만 표시 (웹 공개 폴더만 진입 가능)
- 로그인 회원: 전부 표시, Plaza의 두 종류 폴더 모두 진입 가능

## 5. Phase 37과의 연계점 (구체)

| 항목 | Phase 37의 임시 상태 | Phase 38에서의 처리 |
|------|----------------------|---------------------|
| 공개토론 세션 자동 생성 | `ensurePublicSession()` 함수만 정의, 호출 안 됨 | folder.category가 team/public_*로 바뀌는 시점(또는 그 카테고리에서 문제 생성 시) 자동 호출 |
| AI 활성 게이트 | 모든 문제 AI 가능 | `/api/discuss` 라우트 + 토론 패널 UI에서 `folder.category === 'my' \|\| 'team'` 검사 추가 |
| AI 응답 보안 규칙 | `isOwnerCmt()` 단독 | `isOwnerCmt() \|\| (folder.category === 'team' && isTeamMember(folder.teamId))` |
| 토론 패널 권한 | 소유자만 입력 가능 | 가시성·역할 기반으로 입력/세션 생성 권한 분기 |

## 7. 본 설계 회의에서 결정할 사항

1. **비공개 → 공유 전환 시 정책**: 폴더를 My에서 Team으로 옮기면 그 안의 모든 문제가 일괄 공유됨. 의도치 않은 노출 방지 위해 확인 모달? 별도 "공유로 이동" 작업 분리?
2. **소유권 이전**: 팀에 속한 문제의 소유자가 팀을 떠나면 어떻게? 소유권 팀장에게 이전? 비공개로 회수?
3. **Plaza 폴더 생성 권한**: 누구나 만들 수 있나? 관리자 승인? 초기엔 소유자만 본인의 Plaza 폴더 가능?
4. **비로그인 댓글의 익명성**: 별명 입력? IP 해시? 완전 익명?
5. **공개토론 세션의 댓글 제한**: 공개 문제에서 댓글 길이/속도 제한?
6. **검색·발견**: Plaza에 들어온 문제는 검색 가능한가? 추천/노출 알고리즘?
7. **신고/모더레이션**: 부적절 댓글/문제 신고 시스템 필요 여부 (Phase 35 분리 가능)
8. **삭제 정책**: 공개된 문제를 비공개로 되돌릴 때 기존 외부 링크는 어떻게?
