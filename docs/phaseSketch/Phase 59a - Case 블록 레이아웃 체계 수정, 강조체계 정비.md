Phase 59a : Case 블록 레이아웃 체계 수정, 강조체계 정비

1. Case 블록 레이아웃 체계 수정  
   1. 기조 : rail과 토글 버튼의 위치를 본문영역의 왼쪽 바깥으로 내보내고, rail 때문에 신설한 복잡한 2단 들여쓰기 구조를 모두 없앤다.  
   2. 구체적 내용  
      1. 경우 블록, 하위 경우 블록의 왼쪽 rail의 가로 위치를 본문 영역의 왼쪽 바깥으로 내보낸다.  
      2. 경우 블록, 하위 경우 블록에 대한 왼쪽 여백 들여쓰기 구조를 없앤다. 즉, 경우 블록, 하위 경우 블록 모두 문단의 왼쪽 시작 위치가 일반 텍스트 블록과 동일하고, 별도의 들여쓰기를 하지 않는다.  
      3. 그림 블록, 경우블록과 경우 블록 사이에 있는 블록의 컨텐츠가 rail에 걸리는 것을 방지하기 위하여 해당 블록의 왼쪽 여백 들여쓰기 구조역시 없앤다.   
      4. 여백 확보 : 이를 위해 ProblemView, EditorView, 공유 화면에서 컨텐츠 본문 영역의 왼쪽 여백을 추가로 확보한다.   
         1. ProblemView : 문제 라벨, 풀이 라벨과 본문 텍스트 사이에 rail이 들어갔을때 rail의 좌우에 충분한 여백이 확보되어 시각적으로 답답하거나 불편하지 않아야 한다.  
         2. EditorView : 편집 영역과 미리보기 영역 사이에 추가로 여벽을 확보하여야 한다.  
         3. 공유 화면 : 1\. 에서와 같은 기준 적용하고, 컨텐츠 영역이 2단(문제, 풀이)으로 보일 경우 충분한 사이 여백을 확보한다.  
2. ‘강조문 블록’ 의 명칭 변경  
   1. 명칭 변경 : ‘강조문’ 블록에서 ‘들여쓰기’ 블록으로 변경  
   2. 취지 : 애초 도입 목적이 수식을 포함한 문장 또는 독립적인 문장으에 인용 참조번호를 붙이기 좋게 별도 들여쓰기된 문단이 필요해서였음. 강조 개념이 아님을 뒤늦게 깨달음  
   3. 추가 명칭 변경 : ‘빈 글상자’ 블록을 ‘글상자’ 블록으로 변경  
3. 강조와 ‘요약에 넣기’의 구조적, 개념적 구별  
   1. 강조  : \*\*…\*\*  
      1. 버튼 이름 변경 : ‘핵심문장(\*\*로 강조)’ 를 ‘강조(\*\*...\*\*)’로 변경  
      2. 강조된 영역을 요약에서 별도로 보여주는 기능은 삭제한다.   
      3. 텍스트 또는 수식에서 의미상 강조해야 하는 것. 요약에 들어가고 말고와 무관하게 강조된다.  
      4. 본문의 톤다운을 기본설정으로 : 강조 영역이 있고, 없고에 따라 본문의 톤다운 유무가 결정되던 기본 방식을 버리고 다음과 같이 구조를 단순화한다.  
         1. 본문의 기본 글꼴 톤(수식 포함)을 현재의 강조문구가 들어갔을때의 강조 아닌 컨텐츠의 톤 다운된 상태를 기본 설정으로 한다.  
         2. 강조 (\*\*...\*\*)영역은 현재와 같이 진하게.
