## 0. P절 방향 재수정 (v2 → v3)

v2는 양쪽 다 **"스크롤하면 문제 카드를 숨긴다"**를 전제로, 그때 생기는 화면 튐을
어떻게 보정할지를 설계했다(web v2 R-1·R-2·P2~P5, CLI v2 W3). 덕수 실사용 판정:

> 체감하는 중요한 문제점은 **시각적 안정감이 줄어들어 보인다**는 것. 카드가 사라지고
> 나타나는 순간 화면이 튄다는 느낌.

→ **숨기지 않는다.** 문제 카드는 그냥 흐름대로 위로 밀려 사라지고, 역방향 스크롤로
내려온다. 레이아웃이 바뀌지 않으므로 **튐이 구조적으로 불가능**해진다.
"문제에서 뭐라고 했더라?"는 **누르고 있는 동안만 카드가 화면 중앙에 뜨는** 방식으로 푼다.

### 0-1. 이 전환으로 **폐기**되는 v2 설계

| 폐기 | 사유 |
|---|---|
| 숨김 임계값(web R-1 "카드 하단 ≤ 컨테이너 상단"에서 숨김) | 숨기지 않으므로 불필요. 같은 **판정식은 버튼 표시에만** 재사용한다 |
| `scrollTop` 보정(web R-2·P3, CLI W3) | 레이아웃 불변 → 보정할 것이 없다 |
| 복원 시 최상단 스크롤(web P4) · 반복 숨김 정책(P5) | 복원 개념 자체가 없다 |
| `questionShown` · `hiddenOnce` 상태 | 없다 |
| 왕복 시 읽던 자리 상실(CLI 보완 G2) | 발생하지 않는다 |
| ⚠ **참조 말풍선 회귀 위험(A-2)** — 카드 언마운트/`visibility:hidden` 우회 | **원천 소멸.** 카드가 항상 정상 상태로 DOM에 있으므로 보기의 정의부가 늘 살아 있다. 이번 작업 최대 회귀 지점이 설계 하나로 사라졌다 |
| **Q절 전체**(sticky 선 요소 · 카드 안 페이드 · `scrolled` 상태) | 아래 §0-3 |

### 0-3. Q절(풀이 카드 선·페이드) 폐기 — 메모 항목 2 취소 (덕수, 2026-08-30)

선과 페이드는 **sticky 문제 카드 구조 전용 처방**이었다 — "카드가 선 밑으로 밀려 들어가
사라진다"를 연출하려던 것인데, P2로 sticky를 떼면서 **밀려 들어갈 대상 자체가 없어졌다.**
연출을 위한 장치를 남기면 "안정감 있고 보수적으로"라는 기준과도 어긋난다.

⚠ 이 폐기는 **v3 내부의 모순도 함께 정리한다** — Q절(web v2 승계)은 `scrolled` 상태를 쓰는데
§3 상태 기계에는 `problemOffscreen`·`peeking` 둘만 적혀 있었다. Q를 걷어내면 일치한다.

**다만 그냥 없애면 새 구멍이 생긴다**: 제목행과 스크롤 영역이 **둘 다 아이보리**라,
M2의 슬림 전용 `borderBottom`이 P1으로 사라지면 **제목행 아래에 선이 아예 없어진다.**
클레이 카드가 보이지 않는 경계에서 잘려 "왜 잘렸지"가 된다.

→ **선은 남기되 sticky 요소가 아니라 제목행의 상시 `borderBottom`으로**(P18).
   나타났다 사라지지 않으므로 안정감 기준에 맞고, EditorView Row1이 이미 쓰는 값과
   **같은 문법**이 되어 두 화면의 첫 가로선이 통일된다.

### 0-4. 알약 위치 = 좌측 라벨 거터 (덕수, 2026-08-30)

> "문제보기 버튼의 위치도 제목행일 필요 없겠어. **풀이 라벨 바로 위**가 더 직관적이야."

실측(`TabBody.tsx:83·224-231`)한 구조:

```
[라벨 열 7em]  gap  [카드 widthEm]
   풀이 📋 요약        ← 이 **열 전체**가 sticky
```

⚠ **문제 탭 라벨은 sticky가 아니고 풀이 탭 라벨만 sticky다**(`isQuestion ? null : {...}`).
스크롤하면 거터에 `풀이`만 따라 내려오고, **그 바로 위는 방금 `문제` 라벨이 밀려 올라간 자리다.**
버튼이 "문제가 있던 그 자리"에 서므로 제목행 우측 끝보다 직관이 강하다.

**구조적으로도 더 안전하다**: 버튼을 sticky 라벨 열 안에 `position:absolute`로 띄우면
(sticky는 positioned라 containing block이 된다) **흐름 높이를 차지하지 않는다** →
등장·소멸이 아무것도 밀지 않는다. 옛 P5의 '자리 예약'이 통째로 불필요해진다.

## 2. 결정표

### P. 제목행 고정 + 문제 카드 자연 스크롤 + hold-to-peek **(전면 재작성)**

| # | 결정 |
|---|---|
| **P1** | 제목행 자동접힘 철거. `headerSlim`·`HEADER_H`·`M2_COLLAPSE`·슬림 축약 제목·`borderBottom` 분기·D49 컨트롤 top 연동(`16` 고정)·`font-size`/`height` 트랜지션 삭제. 제목행은 **`height: 98` 고정**(web R-11 — `minHeight`면 줄바꿈 시 커져 EditorView와의 y=98 가로선 정렬이 깨진다) |
| **P2** | ⚠ **문제 카드를 숨기지 않는다.** sticky도 떼고(E-P4) 그냥 흐름에 둔다. 스크롤하면 위로 밀려 사라지고 역방향으로 내려온다. **레이아웃을 바꾸는 코드가 없다** = 튐·진동이 구조적으로 불가능 |
| **P3** | `problemOffscreen` 상태 하나: `onScroll`에서 `rowRef.getBoundingClientRect().bottom <= container.getBoundingClientRect().top`. **버튼 표시만** 좌우하고 레이아웃은 건드리지 않는다. 경계 깜빡임은 **등장 ≤0px / 소멸 ≥8px 히스테리시스** + `opacity` 0.15s |
| **P4** | 알약 버튼: `--accent-primary` · 흰 글자 12px/600 · radius 999 · `padding 4px 10px`(기존 '보기' 알약과 같은 규격). 라벨은 **'문제'** 한 단어(V5′ 재수정 — N-7의 폭 제약 + 거터에서 밀려 올라간 `문제` 라벨의 자리를 그대로 잇는다). 누르고 있는 동안만 보인다는 것은 `title`이 보완한다. **`problemOffscreen`일 때만** 보인다 |
| **P5** | (§0-4) 버튼 위치 = **좌측 라벨 거터의 풀이 라벨 바로 위**. sticky 라벨 열 안에 `position:absolute; bottom:calc(100% + 6px); left:0`. ⚠ **흐름 높이 0이라 등장·소멸이 아무것도 밀지 않는다** — 자리 예약이 필요 없다(옛 P5 폐기). 제목행은 손대지 않는다 |
| **P5-1** | ⚠ 풀이 라벨 열의 sticky top을 **`12 → 40`으로 상수 상향**(버튼 22 + 간격 6 + 12). 안 하면 버튼이 y≈−16이라 **스크롤 영역 상단에 잘린다.** 상수라 튐이 없고, **고정되지 않은 상태에서는 sticky top이 아무 효과가 없어** 라벨은 지금처럼 `paddingTop:14`로 카드 첫 줄에 정렬된 채다 |
| **P5-2** | 고정된 알약은 **위로 흘러가는 내용 위에 그려져야** 한다. sticky 라벨 열은 positioned라 일반 흐름 위에 칠해지므로 배선은 이미 있다 — ⚠ 다만 v3에서 문제 행의 sticky가 사라지므로 `TabBody:222-224`의 "문제 행(z 상위)에 상시 가려진다(v3 W7)" 주석과 `--m2-q-sticky-h`는 **함께 폐기**한다 |
| **P6** | **hold-to-peek**: `pointerdown`에 카드가 화면 중앙에 뜨고 `pointerup`에 즉시 사라진다. 토글이 아니다 — 손을 떼면 원상복귀라 "되돌리는 것을 잊는" 상태가 없다 |
| **P7** | ⚠ **`setPointerCapture` 필수** — 누른 채 버튼 밖으로 나가서 떼면 `pointerup`을 못 받아 **카드가 안 닫힌다**. `pointercancel`·`blur`·`visibilitychange`에서도 닫을 것. 터치 대비 `touchAction:'none'`·`userSelect:'none'`·`contextmenu` 차단 |
| **P8** | 키보드 등가물: `Enter`/`Space` **keydown → 열기 / keyup → 닫기**(`role="button"`). ⚠ keydown은 길게 누르면 **반복 발화**하므로 이미 열려 있으면 무시할 것 |

| **P10** | **딤 없음.** 배경과의 구분은 **`--drawer-shadow`**(우측 패널 4종이 쓰는 2겹, 아래로 떨어지는 그림자)가 담당한다. 딤은 모달의 어휘라 "잠깐 앞으로 나온 카드"와 어긋난다. 실물에서 부족하면 `rgba(0,0,0,0.06)`이 다음 단계 |

| **P12** | 등장 `opacity` **0.08s fade-in**, 사라질 때는 **즉시**. hold는 즉각성이 생명이고, 뗄 때 지체가 있으면 "손을 뗐다 = 닫혔다"가 흐려진다 |

| **P14** | '문제' 라벨은 **띄우지 않는다** — 좌측에 빈 열이 생겨 카드가 중앙에서 어긋나 보인다. 맥락은 버튼이 이미 준다 |

## 3. 상태 기계 (P절 전부)

```
상태: problemOffscreen (기본 false) · peeking (기본 false)
      ⚠ 둘 다 레이아웃에 영향이 없다 → 진동이 구조적으로 불가능

[스크롤] 카드 하단 ≤ 컨테이너 상단        → problemOffscreen = true   (버튼 fade-in)
[스크롤] 카드가 8px 이상 다시 보임         → problemOffscreen = false  (버튼 fade-out)
[버튼 pointerdown / Enter·Space keydown]  → peeking = true   (중앙 카드 0.08s fade-in)
   ⚠ problemOffscreen ⟹ 풀이 라벨은 이미 고정된 상태다(N-8) — 버튼이 뜰 자리가 항상 확보돼 있다
[pointerup / pointercancel / blur / keyup] → peeking = false  (즉시)
[문항 전환]                                → 둘 다 false
```

`scrollTop`을 쓰는 코드가 **하나도 없다** — 판정은 rect 비교뿐이고 보정은 존재하지 않는다.
Q절 폐기로 `scrolled` 상태도 없다(§0-3) → 스크롤이 만드는 상태는 `problemOffscreen` **하나**뿐이다.

## 7. 하지 말 것

- ⚠ **문제 카드를 숨기거나 언마운트하지 말 것**(P2). v3의 값 전부가 여기서 나온다 — 숨기는 순간
  튐·보정·진동·말풍선 회귀가 한꺼번에 돌아온다.
- ⚠ **중앙 카드를 `[data-ref-tooltip]` 안에 두지 말 것**(P13·N-1).
- ⚠ **`setPointerCapture` 없이 hold를 만들지 말 것**(P7) — 안 닫히는 카드가 남는다.
- 별도 팝업 크롬(제목바·닫기·모달 테두리)을 만들지 말 것(P9) · 딤을 먼저 넣지 말 것(P10).
- ⚠ **sticky 선 요소·카드 내 페이드·`scrolled` 상태를 만들지 말 것**(§0-3) — web v2 Q절은 폐기됐다.
  제목행 아래 경계는 `borderBottom` 한 줄(P18)이 담당한다.
- ⚠ **알약을 라벨 열의 흐름에 넣지 말 것**(P5) — 그 순간 라벨이 아래로 밀려 카드 첫 줄과의 정렬이
  깨지고, 토글할 때마다 그만큼 튄다. `position:absolute`로 흐름 밖에 둘 것.
- ⚠ **P5-1 없이 알약을 얹지 말 것** — 라벨이 `top:12`면 그 위 알약은 잘려서 안 보인다.
- 알약을 제목행에 두지 말 것(§0-4에서 폐기) · 제목행에 새 컨트롤을 더하지 말 것.
- S1 전에 R2 금지(B-5) · R3 전에 S3 금지 · `CARD_PAD_*`를 px로 되돌리지 말 것.
- 톤을 형제 오버레이로 만들지 말 것(S7) · `--case-dot-fill` 재정의를 빠뜨리지 말 것(S6).
- 제목 줄 chevron까지 없애지 말 것 · 경우 구역을 div로 감싸지 말 것(D15′).
- 제목행을 `minHeight`로 두지 말 것(R-11).
- M2 규약(우측 패널 4종 규격 · 밝기 3단 서열 · 드로어 1행 48 · 본문 컨테이너 block · 하단 스페이서)은 건드리지 않는다.
