## 0. P절 방향 재수정 (v2 → v3)

v2는 양쪽 다 **"스크롤하면 문제 카드를 숨긴다"**를 전제로, 그때 생기는 화면 튐을
어떻게 보정할지를 설계했다(web v2 R-1·R-2·P2~P5, CLI v2 W3). 덕수 실사용 판정:

> 체감하는 중요한 문제점은 **시각적 안정감이 줄어들어 보인다**는 것. 카드가 사라지고
> 나타나는 순간 화면이 튄다는 느낌.

→ **숨기지 않는다.** 문제 카드는 그냥 흐름대로 위로 밀려 사라지고, 역방향 스크롤로
내려온다. 레이아웃이 바뀌지 않으므로 **튐이 구조적으로 불가능**해진다.
"문제에서 뭐라고 했더라?"는 **누르고 있는 동안만 카드가 화면 중앙에 뜨는** 방식으로 푼다.

### 0-1. 이 전환으로 **폐기**되는 v2 설계

| 폐기 | 사유 |
|---|---|
| 숨김 임계값(web R-1 "카드 하단 ≤ 컨테이너 상단"에서 숨김) | 숨기지 않으므로 불필요. 같은 **판정식은 버튼 표시에만** 재사용한다 |
| `scrollTop` 보정(web R-2·P3, CLI W3) | 레이아웃 불변 → 보정할 것이 없다 |
| 복원 시 최상단 스크롤(web P4) · 반복 숨김 정책(P5) | 복원 개념 자체가 없다 |
| `questionShown` · `hiddenOnce` 상태 | 없다 |
| 왕복 시 읽던 자리 상실(CLI 보완 G2) | 발생하지 않는다 |
| ⚠ **참조 말풍선 회귀 위험(A-2)** — 카드 언마운트/`visibility:hidden` 우회 | **원천 소멸.** 카드가 항상 정상 상태로 DOM에 있으므로 보기의 정의부가 늘 살아 있다. 이번 작업 최대 회귀 지점이 설계 하나로 사라졌다 |

### 0-2. 확정된 미결 항목

|---|---|

### P. 제목행 고정 + 문제 카드 자연 스크롤 + hold-to-peek **(전면 재작성)**

| # | 결정 |
|---|---|
| **P1** | 제목행 자동접힘 철거. `headerSlim`·`HEADER_H`·`M2_COLLAPSE`·슬림 축약 제목·`borderBottom` 분기·D49 컨트롤 top 연동(`16` 고정)·`font-size`/`height` 트랜지션 삭제. 제목행은 **`height: 98` 고정**(web R-11 — `minHeight`면 줄바꿈 시 커져 EditorView와의 y=98 가로선 정렬이 깨진다) |

## 3. 상태 기계 (P절 전부)

```
상태: problemOffscreen (기본 false) · peeking (기본 false)
      ⚠ 둘 다 레이아웃에 영향이 없다 → 진동이 구조적으로 불가능

[스크롤] 카드 하단 ≤ 컨테이너 상단        → problemOffscreen = true   (버튼 fade-in)
[스크롤] 카드가 8px 이상 다시 보임         → problemOffscreen = false  (버튼 fade-out)
[버튼 pointerdown / Enter·Space keydown]  → peeking = true   (중앙 카드 0.08s fade-in)
[pointerup / pointercancel / blur / keyup] → peeking = false  (즉시)
[문항 전환]                                → 둘 다 false
```

`scrollTop`을 쓰는 코드가 **하나도 없다** — 판정은 rect 비교뿐이고 보정은 존재하지 않는다.
