## 0. 묶음 원칙 — 7항목 → 4질문

| 덕수 항목 | 질문 | 잣대(한 질문 = 한 잣대) |
|---|---|---|
| 1 문제오류(답 없음·복수) · 3 선지·정답 오류 | **P1 성립** | "이 문제는 답이 하나로 서는가" — 직접 풀어야 알 수 있는 것들 |
| 2 표기오류 · 5 오해·모호한 표현 | **P2 표기·표현** | "읽는 사람이 다르게 읽을 수 있는가" — 풀지 않고 읽기만 해도 보이는 것들 |
| 4 과조건 · 군더더기 | **P3 과조건·군더더기** | "지워도 되는가" — 풀이 G2와 같은 삭제 축 |
| 6 더 나은 표현 · 7 조건·발문 수정(수치 단순화·겹침 제거·간결화) | **P4 개선 재작성** | "다시 써라" — 풀이 G3와 같은 재작성 축 |

P3↔G2, P4↔G3가 같은 축이라 문제·풀이가 대칭이 된다. 실험에서 "삭제 축이 재작성 축보다 나은가"를 문제·풀이 양쪽에서 같이 볼 수 있다.

**전제가 G와 다르다.** G1~G3는 "정상 문항" 전제를 깔았지만 P는 문제 자체를 의심하는 질문이라 전제를 깔지 않는다.

**풀이 참고 여부가 질문마다 다르다.** discuss 컨텍스트는 문제 + 풀이·참고 탭을 늘 함께 싣는다(`CommentPanel:554-583`). 그래서 문안이 명시한다 — P1은 **풀이를 보지 말 것**(독립적으로 풀어야 답의 존재·유일성이 검증된다), P3·P4는 **풀이를 참고할 것**(어느 조건이 어디서 쓰이는지, 어떤 수치가 계산에 나오는지는 풀이가 알려 준다).

**등록 정답은 넘기지 않는다(66a D11 유지).** P1이 "네가 구한 답을 첫 줄에" 적게 하고 덕수가 눈으로 대조한다. `Problem.answer`가 discuss 컨텍스트에 없어 치환이 필요한데(66 v1 `{answer_line}`), 1단계는 코드 0을 지키고 후속에서 넣는다. 선지 포함 여부·단답형 자연수 여부는 등록 정답 없이도 모델이 판정할 수 있다.

**D15′(히스토리 미첨부) 때문에 질문끼리 이어지지 않는다.** 항목 6의 "발견된 오류를 제거한" 재작성은 P1~P3의 답을 P4가 볼 수 없으므로, P4가 **스스로** 오류·모호함을 보며 고치도록 자기완결로 썼다.

**트리거 낱말 검사 통과.** 넷 다 `검산`·`sympy`·`파이썬으로`·`코드로 확인/검증/계산`·`계산해 확인`·그래프 그리기 결합형이 없다(66a D20·T7).

## 1. 문제 검증 4개 (`target: 'problem'`)

### P1 · 문제(성립) — 답의 존재·유일성·선지 `order 10`
```
풀이는 보지 말고 문제만으로 직접 풀어서 답을 구해줘. 첫 줄에 네가 구한 답을 적어줘.
그다음 이 문제가 성립하는지 봐줘:
- 조건을 만족하는 답이 없거나 둘 이상이면, 어느 조건이 부족하거나 서로 충돌하는지 짚어줘.
- 객관식이면 네 답이 선지에 있는지, 옳은 선지가 둘 이상은 아닌지, 선지끼리 형식(기약분수·유리화·단위)이 맞는지 봐줘.
- 단답형이면 네 답이 1 이상 999 이하의 자연수인지 봐줘 — 아니면 문제나 조건이 잘못된 거야.
답을 확정하지 못했으면 어디서 막혔는지 적어줘. 문제에 없는 조건을 네가 보태서 넘기지 마 — 그 자리가 곧 지적이야.
수식은 $...$로 감싸.
```

### P2 · 문제(표기·표현) `order 20`
```
문제 본문의 표기와 표현만 봐줘. 답이 맞는지는 보지 마. 사소한 것이라도 빠짐없이:
- 같은 문자가 서로 다른 뜻으로, 또는 다른 문자가 같은 뜻으로 쓰인 곳
- 수학 용어나 기호를 잘못 쓰거나 어색하게 쓴 곳 — 구간·집합·함수 표기, 첨자·괄호·로그 밑, 발문의 어투처럼 수능 문항의 관습과 어긋나는 것

각 지적마다 원문을 짧게 인용하고, 어떻게 잘못 읽힐 수 있는지와 고친 문안을 적어줘.
지적이 많으면 답변 길이 제한보다 빠짐없이 적는 쪽을 우선해. 수식은 $...$로 감싸.
```

### P3 · 문제(과조건·군더더기) `order 30`
```
문제의 조건 하나하나가 답을 구하는 데 실제로 쓰이는지 봐줘. 풀이가 있으면 각 조건이 풀이의
어느 지점에서 쓰였는지 짚고, 없으면 네가 풀면서 어디서 쓰는지 봐.
- 그 조건을 지워도 답이 그대로 하나로 정해지면 과조건이야.
- 다른 조건에 이미 담긴 내용을 되풀이하거나 의미가 일부 겹치는 조건, 같은 말을 두 번 하는 서술은 군더더기야.
사소한 것이라도 빠짐없이 찾고, 각각 지워도 되는 근거(지운 뒤에도 답이 유일한 이유)와 삭제 문안을 적어줘.
단, 답의 존재나 유일성을 보장하는 데 필요한 조건(자연수·양수·정의역·서로 다른 점 등)은 과조건이 아니야.
지적이 많으면 답변 길이 제한보다 빠짐없이 적는 쪽을 우선해. 수식은 $...$로 감싸.
```

### P4 · 문제(개선 재작성) `order 40`
```
이 문제를 더 나은 문제로 다시 써 줘. 묻는 것과 풀이의 핵심 아이디어는 그대로 두고, 세 가지를 목표로:
① 계산 부담을 줄일 것 — 풀이 과정에서 다루는 수가 1~3자리 정수, 인수분해가 필요하면 2자리 이하 정수가 되도록
   계수·조건의 수치를 조정하고, 기계적으로 반복되는 계산이 있으면 그 반복이 사라지게.
② 의미가 겹치는 조건을 하나로 합치거나 지워서 논리적으로 군더더기 없게.
③ 길고 장황한 수식·서술을 짧고 명료하게 — 읽는 시간과 부담을 줄여 수학적 본질에 집중하게.
오류나 모호한 표현이 보이면 그것도 함께 고쳐.
먼저 고쳐 쓴 문제 전문을 적고, 그 아래 바꾼 곳마다 "원문 → 수정안 → 이유"를 항목으로 정리해줘.
수치를 바꿨으면 바뀐 답도 함께 적어줘. 수식은 $...$로 감싸.
```
