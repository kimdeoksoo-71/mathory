좋은 질문이에요. 두 현상은 사실 하나의 원인, 즉 한글 IME의 "조합(composition)" 상태에서 나옵니다. Mathory 코드(`MarkdownEditor.tsx`, `BlockEditor.tsx`, `lib/latex-highlight.ts`)를 확인하고 답할게요.

## **1\. 밑줄(underline)의 정체 — 조합 중 상태**

한글 두벌식 입력은 자모를 한 타씩 쌓아 음절을 만드는데, **마지막 음절이 완성됐는지는 다음 키를 봐야만 알 수 있습니다.** 예를 들어 ㄱ→ㅏ→ㅇ까지 치면 화면에는 "강"이 보이지만, 다음에 ㅏ가 오면 받침 ㅇ이 다음 음절 초성으로 넘어가 "가아"가 됩니다. 그래서 IME는 마지막 글자를 "아직 미확정(조합 중)" 상태로 들고 있고, macOS는 이걸 밑줄로 표시합니다. space·쉼표·마침표·화살표키 같은 "한글 자모가 아닌 입력"이 들어오거나 포커스가 빠져나가야 비로소 확정(commit)됩니다. 이 부분은 OS 차원의 동작이라 **불가피**합니다.

## **2\. 왜 블록을 만들면 글자가 2개가 되는가**

이건 웹 에디터의 고전적인 IME 버그 패턴이고, Mathory 구조에서 벌어지는 일은 이렇습니다.

1. CodeMirror 6는 조합 중인 글자도 실시간으로 문서에 반영합니다. 즉 밑줄 달린 "려"도 이미 에디터 문서(그리고 `onChange`를 타고 React state)에 들어가 있습니다.  
2. "+ 블록 추가"를 클릭하면 에디터가 포커스를 잃고, macOS IME가 조합 중이던 "려"를 확정하면서 `compositionend`와 함께 텍스트를 한 번 더 밀어넣습니다.  
3. 같은 순간에 React가 블록 추가로 리렌더링을 하면서 CodeMirror의 조합 추적이 깨지고, 이미 문서에 있던 글자를 "새 입력"으로 다시 읽어 → "…되어버려**려**"가 됩니다.

Mathory에는 이 문제를 키우는 요인이 하나 더 있습니다. `latex-highlight.ts`의 플러그인이 **매 업데이트마다 문서 전체에 mark decoration을 다시 씌우는데**(모든 일반 텍스트에도 `cm-base-text`를 입힘), 조합 중인 글자 주변의 DOM 텍스트 노드를 건드리는 것은 CodeMirror 공식 문서에서도 경고하는 composition 파괴의 대표 원인입니다.

## **3\. 피할 수 있는가 — 있습니다 (앱 레벨에서)**

두 가지 수정을 권합니다. 둘 다 적용하는 게 안전합니다.

**수정 A — 조합 중에는 하이라이트 데코레이션 재계산을 멈추기** (`lib/latex-highlight.ts`)

update(update: ViewUpdate) {  
  // 한글 조합 중에는 DOM을 건드리지 않고, 기존 데코레이션 위치만 이동  
  if (update.view.composing) {  
    this.decorations \= this.decorations.map(update.changes);  
    return;  
  }  
  if (update.docChanged || update.viewportChanged) {  
    this.decorations \= buildDecorations(update.view);  
  }  
}

**수정 B — 블록 구조를 바꾸기 전에 조합을 먼저 확정시키기** (`BlockEditor.tsx`)

const blocksRef \= useRef(blocks);  
useEffect(() \=\> { blocksRef.current \= blocks; }, \[blocks\]);

// 조합 확정 → 확정으로 인한 state 반영이 끝난 다음 틱에 실행  
const afterCommitIME \= (fn: () \=\> void) \=\> {  
  const el \= document.activeElement;  
  if (el instanceof HTMLElement) el.blur();  
  setTimeout(fn, 0);  
};

const handleAddBlock \= () \=\> {  
  afterCommitIME(() \=\> {  
    const newBlock: BlockData \= { id: \`block-${Date.now()}\`, type: 'text', raw\_text: '' };  
    onChange(\[...blocksRef.current, newBlock\]);   // stale state 방지를 위해 ref 사용  
    setActiveBlockId(newBlock.id);  
  });  
};

포인트는 두 가지입니다. `blur()`로 IME 확정을 **리렌더링과 분리된 시점**에 먼저 끝내고, 확정 시 `compositionend` → `onChange`로 들어온 최신 blocks를 `blocksRef`로 읽어서 유실 없이 블록을 추가하는 것. 같은 패턴을 블록 삭제, 타입 변경, 저장 버튼, 드래그 시작에도 적용해 주는 게 좋습니다.

참고로 어느 쪽이 주범인지 간단히 확인하는 방법: 조합 중(밑줄 상태)에서 블록 추가 대신 **미리보기 영역 등 빈 곳을 클릭만** 해보세요. 그때도 글자가 중복되면 수정 A(데코레이션) 쪽이 주범이고, 클릭만으로는 멀쩡한데 블록 추가 때만 중복되면 수정 B(리렌더링 충돌) 쪽이 주범입니다.

정리하면, 밑줄 자체는 한글 입력의 본질이라 못 없애지만, 블록 생성 시 글자 중복은 에디터 쪽에서 막을 수 있는 버그입니다. 원하시면 두 파일의 수정본 전체를 만들어 드릴게요.
