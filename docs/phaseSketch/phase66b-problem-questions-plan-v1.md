## 2. 확정 사실 (`main 5aeae5f` 실측)

### F1. 새 질문이 덕수 목록에 들어가지 않는다

`ensureSeeded`(`lib/askQuestions.ts`)는 목록을 읽어 **비어 있을 때만** 씨앗을 쓴다. 덕수 컬렉션에는 G1~G3가 있으므로
`SEED_QUESTIONS`에 P1~P4를 더해도 **아무 일도 일어나지 않는다**. 초안 §4의 "씨앗 수 3 → 7"은 신규 사용자에게만 참이다.

단순히 "없는 씨앗을 채운다"로 바꾸면 반대 문제가 생긴다 — **덕수가 지운 질문이 다음 열기에 되살아난다.**
그래서 "어느 씨앗을 이미 제안했는가"를 기록해야 한다.

### F2. 문제 질문의 범위 표시가 뒤집힌다

오늘 5aeae5f가 문답 전송을 이렇게 만들었다(`CommentPanel.tsx` `buildContext` `solutionTarget`):

```
※ 검증·지적 대상은 [문제]와 "검증 대상" 표시가 붙은 탭뿐입니다. …
### [풀이] — 검증 대상
### [AI 풀이] — 참고 자료 (검증 대상 아님)
```

이 표시는 **질문의 target을 보지 않는다.** P2(표기·표현)를 보내면 모델은 "풀이도 검증 대상"이라는 안내와 함께 받아
**풀이의 표기까지 지적한다.** 초안 §0의 "discuss 컨텍스트는 문제 + 풀이·참고 탭을 늘 함께 싣는다(`CommentPanel:554-583`)"는
5aeae5f **이전** 서술이다.

### F3. P1의 "풀이는 보지 말고"는 지켜질 수 없다

풀이가 컨텍스트에 실려 있으면 모델은 이미 읽었다. "보지 말라"는 부탁일 뿐이고, 읽은 풀이에 끌린 풀이는
**독립 풀이가 아니다.** 그러면 P1의 존재 이유 — 직접 풀어서 답의 존재·유일성을 확인한다 — 가 약해진다.
**문안으로 막을 일이 아니라 보내지 않아야 한다.**

확인: 서버 `buildUserPrompt`(`route.ts:396`)는 `currentTabContent && currentTabLabel`일 때만 풀이 절을 넣는다 →
클라가 둘을 `undefined`로 보내면 **풀이 절 자체가 없다**. 서버 변경 0으로 된다.

### F4. `$...$`는 말풍선에서 망가지고, 지난번 권한 백틱도 망가진다

**⚠ 66a 후속 턴의 "백틱으로 감싸라" 권고는 틀렸다.** 실행 결과(렌더러 정규식 + 실제 remark-math 파서):

| 문안 | 렌더러 전처리 후 | 말풍선에 보이는 것 |
|---|---|---|
| `수식은 $...$로 감싸.` | `$\displaystyle ...$` | 수식 `…` |
| `` 수식은 `$...$`로 감싸. `` | `` `$\displaystyle ...$` `` | 코드 `$\displaystyle ...$` |
| `수식은 달러 기호($) 한 쌍으로 감싸.` | 변화 없음 | **글자 그대로** |

원인: `EditorPreview`의 인라인 `\displaystyle` 주입(`:228-233`)이 **원문 전체**에 돈다. 보호하는 것은 코드**펜스**뿐이다(`protectFences` `:80`).
인라인 코드 안의 `$…$`도 주입 대상이 된다.

⚠ **AI가 받는 문장은 처음부터 멀쩡했다** — 전송은 전처리 전 원문이다. 대화 기록에서만 틀려 보인다.
⚠ 달러 한 개 문안은 **본문 전체에 `$`가 하나뿐일 때만** 안전하다. 질문에 `$x$` 같은 수식을 함께 쓰면 짝이 엉킨다.

### F5. 트리거 낱말 — P1~P4 통과 (실행 검사)

|---|---|---|---|
| P1 | 없음 | 없음 | 331자 |
| P2 | 없음 | 없음 | 327자 |
| P3 | 없음 | 없음 | 365자 |

§4의 수정 문안(P1 · P4 꼬리)도 다시 검사해 통과했다.

### F6. 잘림·시간 위험이 풀이 질문보다 크다

P1은 **실제로 풀어야** 하고, P4는 **전문 재작성 + 새 문제 재풀이**다. Opus 5는 사고가 기본으로 켜져 있어 사고 토큰도
`maxTokens`에서 깎인다 — 66a 첫 실험에서 한도가 모자라자 **본문이 0자**였다. 실험 문서의 8192는 고난도 P1에서 모자랄 수 있다.
한 요청 예산은 280초이고, 모델이 스스로 코드를 돌리면 요청 안에서 호출이 최대 4회로 곱해진다(66a 규약). P1은 자발적 코드 실행 가능성이 높다.

### F7. 사용자 문서에 표식을 두어도 안전하다

`lib/users.ts`는 문서가 **없을 때만** merge 없는 `setDoc`(`:38`)을 쓰고, 기존 사용자는 `{ merge: true }`(`:51`)다 → 새 필드가 로그인 때 지워지지 않는다.
규칙 `match /users/{userId}`는 본인 쓰기를 허용한다 → **규칙 0.**

### F8. 카테고리 이름이 갈려 있다

편집 모달의 대상 셀렉트가 `해설`(`AskListPopover.tsx`), 초안도 `해설`, 덕수 요청은 **`풀이`**. 앱 전체가 탭 이름으로 `풀이`를 쓴다.

### F9. 수능형 전제가 문안에 박혀 있다

P1 "단답형이면 1 이상 999 이하의 자연수" · P2 "수능 문항의 관습". 수능형이 아닌 문항(경시·교과서형 등)에 돌리면 **오탐**이 된다.
P4는 수치를 바꾼 뒤 **새 문제도 답이 하나인지** 확인하라는 말이 없다 — 재작성이 오류를 새로 만들 수 있다.

### F10. P1·P2는 61b 교차 검증의 문제 검증과 겹친다

61b 문제 검증 1차 태그는 조건결함 · 답없음 · 선택지오류 · 표기다. P1·P2가 같은 영역이라 **대조군으로서 이득**이다(66a가 검증 칩을 남긴 이유와 같다).
초안은 P3·P4의 보완 관계만 적었다.

세 경우 모두 끝에 "이전 대화는 참조하지 않습니다."

**AI가 받는 모양 — 문제 질문 · 탭 함께**

## 문제:
(문제)

## 현재 풀이 (탭: 참고 탭):

### [풀이] — 참고 자료 (검증 대상 아님)
### [AI 풀이] — 참고 자료 (검증 대상 아님)

⚠ 서버가 붙이는 절 제목 "현재 풀이"는 바꿀 수 없다(서버 0). 라벨과 안내 문장이 그 뜻을 덮는다.

## 9. 하지 말 것

- **질문 본문에 `$`를 두 개 이상 쓰지 말 것**(F4) — 달러 한 개 문안은 본문 전체에 `$`가 하나일 때만 글자 그대로 보인다.
- **백틱으로 `$`를 감싸 해결하려 하지 말 것**(F4) — 렌더러가 인라인 코드 안에도 `\displaystyle`을 넣는다.
- **라벨로 씨앗을 대조하지 말 것**(D4) — 덕수가 라벨을 고치면 중복이 생긴다. `seedKey`와 제안 기록으로만.
- **사본에 `seedKey`를 복사하지 말 것** — 사본이 씨앗으로 취급돼 보충 판정이 흔들린다.
- **범위 안내를 질문 문안에 넣지 말 것** — 컨텍스트가 소유한다(66a 규약). 문안은 실험 변수다.
- **탭을 라벨로 거르지 말 것** — id(`solution`)로만(66a 규약).
- 66a 규약 전부(트리거 낱말 · 히스토리 미첨부 · 답글 해제 · 전송 try/catch · 저장 가드).
