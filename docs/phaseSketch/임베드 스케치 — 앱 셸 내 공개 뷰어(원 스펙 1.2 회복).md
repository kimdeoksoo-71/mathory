# 후속 Phase 스케치 — 앱 셸 내 공개 뷰어 임베드 (원 스펙 1.2 회복)

> Phase 53 v2.1의 **U6 포석**을 실행하는 후속 소형 Phase. 번호는 착수 시점에 부여(docs/phaseSketch 보관용).
> 목적: 덕수 원 스펙 **"로그인한 회원: 좌측 사이드바 전체가 뜨는 페이지"**(1.2)를 문항 열람까지 회복 — **규칙 무충돌로.**

---

## 1. 배경 & 근거

Phase 53에서 "공개 열람의 풀 앱 통합"은 규칙 충돌로 철회됐다(`ProblemView`/`CommentPanel`이 `listSessions`·`watchAllComments`에 의존 → 익명 크래시·비멤버 denied). 그래서 로그인 사용자도 문항 열람은 MiniShell로 보게 됐고, 두 가지 아쉬움이 남았다:

1. **원 스펙 후퇴**: 로그인 회원이 풀 사이드바 없이 열람.
2. **UX 어색함**: 앱 안에서 Bazaar 피드를 보다가 게시물 클릭 → 새 탭의 미니 사이드바로 "빠져나감".

핵심 통찰: **리스타일된 공개 뷰어(`PublicProblemView`+`PublicComments`)는 규칙상 로그인-비멤버에서도 완전 동작한다** — 공개 read(`commentStream==true` 필터)·write(`publicCommentsEnabled` 가지)가 정확히 그 시나리오를 위해 만들어졌기 때문. 따라서 **ProblemView를 고치는 게 아니라, 공개 뷰어를 AppShell 콘텐츠 영역에 임베드**하면 풀 사이드바 열람이 규칙 그대로 성립한다.

**선행조건: Phase 53 U6 완료** — 공개 뷰어의 `100dvh` 등 전면 가정이 제거되어 임베드 가능한 형태(`height: 100%`)일 것.

## 2. 목표

1. 로그인 사용자의 공개 문항·스냅샷 열람을 **풀 앱(전체 사이드바) 안에서** 제공.
2. 앱 내 Bazaar 피드 클릭 → **새 탭 이탈 없이** 앱 내 전환.
3. 익명 방문자는 현행 유지(MiniShell — 변경 없음).

## 3. 구현 범위

**3-1. AppShell 딥링크 분기 변경** (Phase 53 §3-C의 확장)
- 현행(53): `?view=p&id=` — 오너면 ProblemView, **비오너면 `/p/{id}` 리다이렉트**.
- 변경: 비오너(로그인)면 리다이렉트 대신 **콘텐츠 영역에 `PublicProblemView` 임베드**(MiniShell 없이 — 사이드바는 AppShell 것). 오너 분기(ProblemView)는 그대로.
- `?view=shared&id=` 동일: 로그인 사용자에게 스냅샷 뷰어 임베드.

**3-2. BazaarView 행 클릭 라우팅 변경**
- 현행: `window.open('/p/...')` 새 탭.
- 변경(로그인 앱 내부에서만): 앱 내 view 전환(`?view=p&id=` 상태) — 뒤로가기 대응은 `history.pushState`. **`/bazaar` 랜딩(익명)은 현행 새 탭 유지.**
- ShareButton이 뿌리는 공유 URL은 **여전히 `/p`·`/shared` 절대경로**(OG 유지) — 앱 내 라우팅과 무관.

**3-3. `/p`·`/shared` 직접 진입(로그인)**
- 선택지 A: 현행 유지(MiniShell) — 임베드는 앱 내 전환에만.
- 선택지 B: 로그인이면 `/?view=p&id=`로 리다이렉트해 풀 앱 임베드.
- **권장 B** — 원 스펙 1.2의 완전 회복. 단 리다이렉트 루프·크롤러 영향 없음 확인(크롤러는 server `generateMetadata`만 소비).

## 4. 리스크

- **R1 (스크롤 계층)**: AppShell 콘텐츠 영역의 overflow 정책과 공개 뷰어 내부 분리 스크롤(2단·댓글 패널)의 중첩 — U6에서 높이 위임이 제대로 됐다면 래퍼 한 겹으로 해결, 안 됐다면 여기서 드러남(수락 기준에 명시).
- **R2 (이중 진입점 혼동)**: 같은 문항이 "앱 내 임베드"와 "MiniShell(/p 직접, 익명)" 두 모습 — 의도된 설계임을 문서화. 기능 차이는 없어야 함(둘 다 동일 컴포넌트).
- **R3 (오너 셀프 열람)**: 오너가 자기 게시물을 피드에서 클릭하면 ProblemView(편집)로 — 임베드가 아니라 기존 오너 분기 유지. 분기 누락 시 오너가 공개 뷰어로 떨어져 편집 불가 혼란.

## 5. 수락 기준

- [ ] 로그인 사용자: 피드 클릭 → 새 탭 없이 풀 사이드바 + 공개 뷰어. 뒤로가기로 피드 복귀.
- [ ] 로그인 사용자 `/p`·`/shared` 직접 진입 → 풀 앱 임베드(선택지 B 채택 시).
- [ ] 오너 클릭 → ProblemView(편집 가능) 유지. 익명 → MiniShell 현행 유지.
- [ ] 임베드 상태에서 댓글 읽기/작성(`publicCommentsEnabled` 문항)·ShareButton(절대경로 URL) 정상.
- [ ] 스크롤 중첩 없음(콘텐츠 영역 1겹 스크롤 정책 준수).
