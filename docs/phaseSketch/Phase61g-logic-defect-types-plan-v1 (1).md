## 0. 요약

시트 STEP3(`QualityVerification.gs`)가 2026-09-06에 **결함 유형 2종 → 6종**으로 넓어졌다. 1차(Gemini)는
"과탐지보다 미탐지를 경계"하는 recall 지향으로 바뀌고, 2차(Claude)는 **유형별 valid 기준**과
"실제 수학적 검증" 절차를 받았다. 코드는 `Q_TYPES` 단일 출처 + 부분 문자열 정규화 + 후보 상한 8→12다.

Mathory 정밀 검증(Phase 61b)은 같은 STEP3를 이식한 것이라 구조가 같다 — 풀이 1차가 **계산·표기 / 논리
두 패스**로 나뉘어 있고(시트의 STEP2/STEP3 분리에 해당), 논리 패스는 태그 4종(`논리비약·논리오류·경우누락·
문제풀이불일치`)이다. 시트 6종 중 **`unwarranted_assumption`(근거 없는 가정)과 `sufficiency_unchecked`
(충분성 미확인)에 해당하는 태그가 없고**, 나머지 넷도 정의가 한 줄이라 시트 V2의 세부 판별 기준이 빠져 있다.

반영은 **프롬프트 2개(논리 패스·2차 판정) + 태그 화이트리스트 2종 추가 + 후보 상한·병합 조정 + 테스트·프로브**로
끝난다. **서버 라우트 로직 0 · Firestore 규칙 0 · 스키마 0 · 리포트 카드 0 · 클라이언트 0.**
(태그는 `VerifyReportCard.tsx:254`가 문자열 그대로 칩에 찍으므로 매핑 표가 없다 — 추가해도 렌더 무변경.)

⚠ 시트 V2 2차 프롬프트의 한 문구("애매해 보인다는 uncertain의 근거가 아니다")는 Mathory 61b가 실측으로
세운 규약(확신 없으면 `invalid`가 아니라 `uncertain`, 기각률 85% 사고)과 **정면으로 충돌**한다. §4 D5에서
**이식 제외**를 제안한다 — "그대로 반영"에서 유일하게 벗어나는 자리이니 덕수 판정을 받는다.

시트는 단일 패스 상한 8→12다. Mathory는 논리 패스가 두 패스 중 하나이고 병합 상한이 12라, 논리 패스만 12로
올리면 `[CALC, LOGIC]` 이어 붙이기에서 **논리 후보가 먼저 잘린다** — 61b 실측에서 놓친 쪽이 바로 논리였다.
제안: 논리 패스 상한 **12**(계산 패스 8 유지) · 병합 상한 **16** · `mergeCandidates`를 **교차 병합**(패스별 배열의
머리부터 번갈아 뽑는다 — 두 패스 다 "의심 강한 것부터" 정렬하므로 절단이 양쪽 꼬리에 고르게 걸린다). 결정적 순서는
유지된다(같은 입력 → 같은 리포트). 대가: 2차 입력이 최대 16건이라 판정 시간·토큰이 는다(§8).
대안 A: 병합 상한만 16으로 올리고 이어 붙이기 유지(8+12=20이라 절단 가능). 대안 B: 순서를 `[LOGIC, CALC]`로 바꾸기
(계산 후보가 잘린다 — 문제를 옮길 뿐).

**D3 — 시트 (F) 불일치의 자리** (덕수 확정 필요)
시트 F는 "같은 대상을 앞뒤에서 다르게 규정 · 앞에서 한정한 범위를 뒤에서 무시"로, Mathory `수식비일관`(계산 패스,
"앞뒤 **식**이 어긋남")보다 넓고 `문제풀이불일치`(문제와 다른 것을 다룸)와는 다르다. 제안: **논리 패스도 `수식비일관`을
발급**할 수 있게 하고 정의를 시트 F로 넓힌다(식뿐 아니라 서술·범위). 신규 태그를 셋으로 늘리지 않으려는 선택이다.
두 패스가 같은 지점을 짚으면 `mergeCandidates`의 인용 중복 제거가 한 건으로 합친다.
대안: B-3 원문 이름이던 `서술비일관`을 논리 패스 전용으로 신설(태그 3종 추가).

**D4 — 2차 유형별 기준의 배치: `PROMPT_JUDGE` 하나에 절로 넣는다** (기본안)
`PROMPT_JUDGE`는 kind·패스 공용이고 요청 phase='judge'는 kind만 알므로, 유형별 기준을 **전 태그**(문제 4 · 풀이 9 ·
공통 1)에 대해 한 절로 적는다. 라우트 분기 0, 테스트의 `P.PROMPT_JUDGE.system` 참조 유지. 논리 6종은 시트 기준을
그대로, 나머지는 한 줄씩(현행 조항을 유형 이름 밑으로 옮기는 정도).

**D5 — 시트 2차 [3] "애매해 보인다는 uncertain의 근거가 아니다"는 이식하지 않는다** (덕수 확정 필요 — 유일한 비이식)
Mathory 61b는 실측으로 반대 규약을 세웠다: `CONSERVATIVE_RULES`(`prompts.ts:129-142`) "걸러 낼 확신이 없으면
invalid가 아니라 uncertain" · CLAUDE.md "2차 페르소나 선언이 세부 규칙을 이긴다(기각률 85%)" · "invalid와
uncertain을 뭉뚱그리면 확신 없는 후보가 조용히 사라진다". 시트 문구는 uncertain을 좁혀 valid/invalid로 몰아가는
방향이라 이 규약과 반대다. 시트 [1]의 **긍정 절차**(재구성·반례·누락 경우 계산 = "무엇을 해서 확신에 이르는가")와
"note에 무엇이 미결인지 구체적으로"는 이식하고, **uncertain을 좁히는 문장만 뺀다.** 시트 쪽은 사람이 V·W열을 보는
운용이고 Mathory는 `check`가 카드에 "확인 필요"로 남아 사람이 보는 구조라, 둘 다 사람이 최종 판단한다는 점은 같다 —
그렇다면 놓치는 쪽 비용이 큰 Mathory 규약을 유지하는 편이 맞다.

**D6 — 1차 논리 패스 이식 범위** (기본안)
시트 [0]·[1]·[2]·[3]·[4]·[5]·[6] 전부 이식하되 Mathory 스키마(`tag/quote/reason/suggestion/block`)와 `RECALL_RULES`·
`COMMON_RULES`는 유지한다. 특히 **[5] "전역 결함은 결론을 확정하는 줄을 인용"은 Mathory에서 시트보다 중요하다** —
`anchorByQuote`가 인용 실재성으로 앵커를 확정하고 실패하면 `check`로 강등하므로, 경우 누락·충분성 미확인처럼
"어느 줄"이 아닌 결함이 허공을 인용하면 **valid 판정이 나도 fail이 되지 못한다.**

**D7 — `normalizeTag` 힌트 확장** (기본안)
`가정/assum/unwarrant`→근거없는가정 · `충분/suffic/uncheck`→충분성미확인 · `추론/infer/invalid`→논리오류를
기존 힌트 앞에 둔다(폴백은 `논리오류` 유지). 충돌 점검: `sufficiency_unchecked`·`unwarranted_assumption`에
`case`·`gap`·`incons`가 들어 있지 않고, `invalid_inference`에 `일관`·`불일치`가 없다 — 순서 무관하게 안전.
시트처럼 정확 일치를 먼저 보는 구조는 이미 같다(`allow.includes(t)`).

**D8 — 계보 주석 갱신** (기본안)
`prompts.ts` 헤더는 "원본은 이 파일, 시트 pmt는 여기서 손복사"라고 적혀 있는데 이번엔 **시트가 앞섰다**. 헤더에
"논리 패스·2차 유형별 기준의 원본은 시트 V2(`dda7bba`)·v4(`95556fc`)이고, 이후 개정은 다시 이 파일이 원본"으로
계보를 남긴다. 61a 규약("GAS 인용은 origin/main + 커밋 해시")과 같은 취지.

## 6. 프롬프트 초안 (착수용 — 프로브 실측에서 확정)

### 6-1. 논리 패스 `PROMPT_SOLUTION_FIRST_LOGIC.system`

```
${SOLUTION_PREAMBLE}

### [1] 이번 검토의 범위 — **논리 전개만**
산술 실수·기호 오기는 **다른 검토자가 따로 봅니다. 여기서는 보지 마십시오.**
숫자가 맞는지가 아니라 **각 줄이 앞줄에서 정말 따라 나오는지**, 그리고 **논증 전체가 최종 답을 실제로 정당화하는지**를 보십시오.
- 최종 답의 정오 자체는 이 검토의 판정 대상이 아닙니다. 그러나 **답이 맞더라도 논증이 그 답을 정당화하지 못하면 결함**입니다.
  "답이 맞으니 괜찮다"는 이유로 후보를 제외하지 마십시오.
- 계산이 아닌 **추론의 잘못**은 이 검토의 대상입니다.

### [2] 태그 (아래 일곱 중 하나)
- "논리비약": 어떤 줄의 결론이 (앞선 줄 + 문제 조건 + 고교 교육과정 내 표준 정리)만으로는 한 단계에 도출되지 않으며,
  그 사이의 근거가 생략됨. 결론 자체는 참일 수 있음.
- "논리오류": 결론이 앞선 내용으로부터 따라 나오지 않는데 따라 나오는 것처럼 서술함.
  · 정리·공식의 적용 조건(연속, 미분가능, 양수, 정의역, 독립 등)을 확인하지 않았거나 만족하지 않는데 적용
  · 필요조건을 충분조건처럼 사용 (예: $f'(a)=0$ 이므로 극값, $D \ge 0$ 이므로 조건 만족)
  · 명제의 역·이를 원명제처럼 사용
  · 동치가 아닌 변형을 동치(⟺)처럼 처리 (양변 제곱, 0일 수 있는 식으로 나눔, 부등식 양변 곱셈 시 부호 미확인,
    로그·제곱근을 취할 때 정의역 미확인 등)
  · 존재하지 않거나 잘못 기억된 정리·성질의 사용
- "근거없는가정": 문제에 명시되지 않았고 앞선 줄에서 도출되지도 않은 사실을 전제로 사용.
  · 함수의 꼴(다항함수, 홀함수, 일대일 등), 변수의 범위·부호, 도형의 위치 관계를 임의로 가정
  · 특수한 경우(특정 값, 대칭 배치)로 풀고 일반적인 결론으로 제시
  · 그림의 '보이는 모양'만으로 특정 관계(수직, 접함, 이등분, 대소)를 단정 — 문제 본문이나 그림의 기호 표기가
    그 관계를 명시한 경우는 제외
- "경우누락":
  · 경우 분류가 완전하지 않음 (부호, 대소 관계, 근의 개수, 정수 조건 등의 일부 경우를 다루지 않음)
  · 방정식·부등식의 해 중 일부만 취하고 나머지를 배제하는 근거가 없음
  · 최대·최소·개수 문제에서 후보 전체를 훑지 않고 결론
- "충분성미확인":
  · 필요조건으로 좁힌 후보값을 문제의 모든 조건에 대해 확인하지 않고 답으로 확정
  · 존재성이 필요한 대상(접선, 교점, 극값, 조건을 만족하는 함수 등)의 존재를 확인하지 않음
  · 최댓값·최솟값에서 등호 성립 조건 미확인
  · 문제 조건 중 풀이에서 한 번도 사용되지 않은 조건이 있음 (그 조건이 후보값을 추가로 제한할 가능성)
  · 단, 앞선 단계가 모두 동치 변형이어서 충분성이 자동으로 보장되는 경우는 제외
- "수식비일관": 같은 대상을 앞뒤에서 다르게 규정하거나, 앞에서 확정한 사실·범위와 뒤의 서술이 모순됨.
  (예: 앞에서 범위를 한정했는데 뒤에서 무시함, 같은 값을 앞뒤에서 다르게 지칭함)
- "문제풀이불일치": 풀이가 문제의 조건·물음과 다른 것을 다룸.
결함이 없으면 빈 배열을 반환합니다.

### [3] 검토 절차 — 두 관점을 모두 수행합니다
1. **줄 단위 검토**: 풀이를 처음부터 한 줄씩 따라가며 각 줄이 (앞선 줄 + 문제 조건 + 표준 정리)에서 어떻게 나오는지
   확인합니다. 나오지 않으면 논리비약·논리오류·근거없는가정 중 해당 태그로 후보에 올립니다.
2. **전역 검토**: 풀이 전체를 놓고 점검합니다.
   · 문제의 각 조건이 풀이의 어느 지점에서 사용되었는가? 사용되지 않은 조건이 있으면 충분성미확인(또는 경우누락) 후보.
   · 풀이가 다룬 경우들이 가능한 경우 전체를 덮는가? 아니면 경우누락 후보.
   · 최종 답으로 확정하기 전에 후보값의 충분성이 확인되었는가? 아니면 충분성미확인 후보.
   · 답이 하나로 확정되기 위해 필요한 논거가 모두 있는가?

**특히 흔한 유형** — 조건이 주는 범위보다 좁게 단정하는 것.
예: "$\pi<\theta<2\pi$ 이므로 $\sin\theta<0$" 은 제4사분면을 빠뜨린 단정입니다.
범위·부호·근의 개수를 단정하는 문장을 만나면 **그 단정이 조건 전체에서 참인지** 확인하십시오.

### [4] 지적하지 않는 것
- 산술 계산의 옳고 그름, 기호 표기 (다른 검토자의 몫).
- 대수적으로 동치인 변형, 다른 풀이 전략, 표기 관습의 차이, 문체·설명의 상세함.
- 고교 교육과정에서 표준으로 통하는 정리·공식의 적용 (적용 조건이 만족되는 경우).
- 자명한 생략: 유능한 고교생이 한 줄로 즉시 재구성할 수 있는 단계.
- 같은 결함을 태그만 바꿔 중복으로 올리지 않습니다. 가장 적합한 태그 하나로 올립니다.

### [5] 인용(quote) 위치
- 결함이 드러나는 지점을 원문 그대로 인용합니다. **경우누락·충분성미확인처럼 전역적인 결함은 결론을 확정하는 줄을
  인용하십시오** — 인용은 원문에 실제로 있는 문자열이어야 위치를 찾을 수 있습니다.

### [6] 후보 순서
심각한 것부터 적습니다: 답의 정당성에 직접 영향을 주는 논리오류·경우누락·충분성미확인 → 근거없는가정 → 논리비약 →
수식비일관·문제풀이불일치. 상한을 넘으면 앞의 것만 판정됩니다.

${recallRules(12)}

${COMMON_RULES}
- 그림에 기호로 표시된 정보(직각 표시, 길이, 각의 크기, 점의 위치 관계)를 근거로 한 단계는 결함이 아닙니다.
  그림의 보이는 모양만으로 관계를 단정한 경우는 근거없는가정 후보가 될 수 있습니다.
  풀이가 그림과 명백히 다른 상황을 전제하고 서술을 이어가면 수식비일관 후보입니다. 그림 판독이 애매하면 reason에
  그 사실을 적고 후보로 올립니다.

${SOLUTION_SCHEMA('논리비약')}
```

`user`는 현행 문장에 태그 이름 일곱을 나열하고 "줄 단위 검토와 전역 검토를 모두 수행하라"를 덧붙인다.
(⚠ `RECALL_RULES` 안의 "한 줄씩 따라 읽으며"와 [3]-1이 겹친다 — 초안은 겹침을 두었고 프로브에서 한쪽을 줄인다.)

### 6-2. 2차 `PROMPT_JUDGE.system`에 넣는 절

```
### [2′] 태그별 valid 기준 — 판정 근거는 실제 수학적 검증이어야 합니다
각 후보마다: quote 지점을 원문에서 찾고 → 문제 조건과 앞선 줄만 사용해 그 지점을 스스로 재구성해 보고
(필요하면 반례를 구성하거나, 누락됐다는 경우가 실제로 가능한지 계산하고) → 아래 기준으로 판정합니다.
"해설 관행상 흔히 생략한다", "답은 맞다"는 invalid의 근거가 아닙니다.

풀이 — 논리
- 논리비약: 그 단계가 (앞선 줄 + 문제 조건 + 고교 표준 정리)만으로 한 단계에 도출되지 않고 생략된 근거가 자명하지
  않으면 valid. 유능한 고교생이 한 줄로 즉시 재구성할 수 있으면 invalid.
- 논리오류: 지적된 추론이 실제로 성립하지 않으면 valid — 적용 조건이 실제로 미충족이거나 확인되지 않았거나,
  역·이·필요/충분 혼동이 실제로 있거나, 비동치 변형이 실제로 해를 추가·제거할 수 있을 때. 필요한 조건이 문제나
  앞선 줄에서 이미 보장되어 추론이 성립하면 invalid (note에 보장 근거 명시).
- 근거없는가정: 사용된 가정이 문제 본문, 앞선 줄, 그림의 기호 표기 어디에서도 나오지 않고 도출되지도 않으면 valid.
  다른 조건으로부터 도출 가능하면 invalid (note에 도출 근거 명시).
- 경우누락: 누락된 경우가 문제 조건 하에서 실제로 가능하면 valid. 문제 조건에 의해 자명하게 배제되면 invalid
  (note에 배제 근거 명시). 배제되기는 하나 자명하지 않은 논거가 필요한데 풀이에 없으면 valid
  (note에 "배제되나 논거 누락"이라고 적고 그 논거를 제시).
- 충분성미확인: 확정된 후보값이 실제로 모든 조건을 만족하는지 직접 확인합니다. 만족하지 않는 후보가 섞여 있거나,
  앞선 단계에 비동치 변형(필요조건으로의 축소)이 있어 충분성 확인이 논리적으로 필요한데 풀이에 없으면 valid.
  앞선 단계가 전부 동치 변형이라 충분성이 자동 보장되면 invalid (note에 그 사실 명시).
- 수식비일관: 실제 모순이거나 기호·양의 지칭 대상이 실제로 바뀐 경우만 valid. 단순 문체·표기 차이는 invalid.
- 문제풀이불일치: 풀이가 다룬 조건·물음이 문제의 것과 실제로 다르면 valid.

풀이 — 계산·표기
- 계산오류: 문제 조건 또는 앞줄의 결과와 실제로 충돌하는 산술 결과일 때 valid. 대수적으로 동치이면 invalid.
- 표기오류: 같은 문자가 서로 다른 의미로, 또는 서로 다른 문자가 같은 의미로 실제로 쓰였을 때 valid. 관습 차이는 invalid.

문제
- 조건결함·답없음·선택지오류·표기: 지적된 상충·누락·비유일·중복이 실제로 성립하는지 스스로 풀어 확인했을 때만 valid.

공통
- 정답불일치: 등록 정답과 도출 답 중 어느 쪽이 맞는지 직접 풀어 가립니다. 등록 정답이 틀렸거나 문제가 결함이면 valid,
  도출이 틀렸으면 invalid (note에 올바른 답과 근거).

- "uncertain"이면 note에 **무엇이 결정되지 않았는지** 구체적으로 적습니다 — 사람에게 '확인 필요'로 보고됩니다.
- 그림에 기호로 표시된 정보는 문제 조건으로 취급합니다. 이를 근거로 한 단계에 대한 결함 주장은 invalid.
  그림의 보이는 모양만으로 단정한 관계는 조건이 아닙니다. 그림 판독이 애매하면 uncertain.
```

`CONSERVATIVE_RULES`와 `[2] 판정 원칙`은 **그대로 둔다**(D5). 페르소나 첫 문장("추려 주는 심판, 문지기가 아니다")도
그대로 — 61b 실측에서 세부 규칙보다 이 문장이 판정 성향을 정했다.

## 8. 위험·트레이드오프

- **2차 시간**: 후보 상한 12→16, 유형별 기준으로 system이 길어진다. 61b 실측은 한 문항 2차가 수십~백여 초였고 예산은
  280초다. Stage 2에서 2차가 200초를 넘는 문항이 나오면 병합 상한을 14로 내린다(D2 폴백).
- **기각률 상승으로 상쇄**: 1차만 넓히면 2차가 더 기각해 상쇄된다(61b 규약 "두 짝을 함께"). 이번엔 2차에 유형별
  **valid** 기준을 주므로 확정이 늘 수도, 기준이 구체적이라 기각이 늘 수도 있다 — Stage 2의 기각률이 61b 베이스라인
  (56%)에서 크게 벗어나면 D5 방향을 재점검한다.
- **`충분성미확인` 소음**: "한 번도 사용되지 않은 조건" 항목은 정의상 후보를 많이 낸다. 시트도 같은 문구라 시트 W열
  (감사)에서 이 유형의 기각률을 함께 보면 신호가 된다.
- **E-4 체계 변경**: 태그 2종 추가는 되돌리기 쉽다(화이트리스트에서 빼면 정규화가 `논리오류`로 흡수) — 저장된 리포트의
  태그는 문자열이라 그대로 남고 카드도 그대로 찍는다.
- **프롬프트 원본이 두 곳**: 시트가 앞서고 Mathory가 따라간 첫 사례다. D8 계보 주석이 없으면 다음 개정 때 어느 쪽이
  원본인지 흐려진다.
