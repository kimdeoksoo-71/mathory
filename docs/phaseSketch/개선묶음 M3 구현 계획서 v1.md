## 2. B4 — 제목바 클릭 상하 떨림: 원인 규명 완료

**"정체불명의 상자"의 실체 = `.outline-section.is-open`의 상시 톤 상자다**(`globals.css:962-968`, v3 S3의 카드 전폭 톤 — 배경 `--block-bg` + radius 6).

떨림의 원인은 그 상자가 아니라 **여는 순간에만 생기는 상하 패딩**이다:

```css
.outline-section.is-open {
  padding-top: 0.3em; padding-bottom: 0.3em;   /* ← 닫힘엔 없다 → 클릭 순간 0.6em 성장 */
}
.outline-section.is-open + .outline-section.is-open { margin-top: 0.4em; }   /* ← 두 번째 밀림원 */
```

좌우는 정확히 이 문제를 피하려고 **상시**로 설계돼 있다(`:955` 주석: *"is-open일 때만 주면 … 열고 닫을 때마다 좌우가 미세하게 움직인다"*) — **상하만 그 처방에서 빠진 것**이다. focus-visible outline(2px)은 비레이아웃이라 무관.

### 처방 (D7)

| 안 | 내용 | 대가 |
|---|---|---|
| **(a) 권장 — 패딩은 유지하고 같은 값의 음수 마진으로 상쇄** | `padding: 0.3em` + `margin-top/bottom: -0.3em` → 톤 상자는 내용보다 0.3em 크게 그려지되 **흐름 높이 불변** | 위·아래 형제와 0.3em 겹침 — 섹션 사이 자연 간격이 그보다 크면 무해(실측 스텝 필요) |
| (b) 상하 패딩을 상시로 | 좌우와 같은 처방 | 접힌 요약의 섹션 간격이 전부 0.6em씩 늘어난다(정적 레이아웃 변화) |
| (c) 상하 패딩 삭제 | 가장 단순 | 톤 상자가 첫·끝 내용에 딱 붙어 답답하다(0.3em을 준 이유가 사라진다) |

`(a)`를 택하면 `.is-open + .is-open { margin-top: 0.4em }`(인접 열림 뭉침 방지)도 같은 종류의 밀림원이므로 **함께** 상쇄형으로 손봐야 한다 — 안 그러면 "이웃이 열려 있을 때만" 떨림이 남아 재발 보고가 온다. ProblemView 디자인 개선의 원칙("튈 일을 만들지 않는다 — 최종 코드에 scrollTop 0")과 같은 계열의 처방이다.

## 3. B3 — '앞부분 펼치기' 헛표시: 원인 규명 완료

전문(前文) 섹션의 여닫이 표시 조건이 **"요약 항목이 있으면"**으로 되어 있다(`OutlineSections.tsx:152`):

```tsx
) : sec.items.length > 0 || (open && sec.blocks.length > 0) ? (
  <Toggler …>{open ? '앞부분 접기' : '앞부분 펼치기'}</Toggler>
```

풀이가 제목 없이 **'요약에 넣기'를 켠 블록(또는 제목행 있는 경우 블록)으로 시작**하면, 그 블록은 items로 스켈레톤에 이미 보이는데 조건은 `items.length > 0`로 참 → 여닫이가 그려진다. 펼치면 `sec.blocks` 전체를 그리는데(`:158`) 그것이 스켈레톤과 같은 내용이라 **아무것도 변하지 않는다.** 메모의 증상 그대로다.

### 처방 (D6)

여닫이는 **"펼쳐야만 보이는 내용이 있을 때만"** 그린다. 판정은 `buildOutline`(`lib/solutionOutline.ts:79`)이 섹션을 만들면서 계산해 `OutlineSection`에 필드로 싣는다(렌더에서 재계산하면 사본 셈법이 된다):

- 숨은 내용 = `sec.blocks` 중 ① kind:'block' 항목으로 통째 노출되지 않았고 ② 경우 항목의 그 case 블록 자신도 아니며 ③ 어떤 경우 구역(segment)에도 속하지 않는 블록 — **경우 구역 내용은 경우 제목 클릭이 담당**하므로 전문 여닫이의 근거가 아니다
- ④ 레거시 승격 텍스트 블록(라벨 **줄만** 노출)은 나머지 줄이 숨어 있으므로 **숨은 내용으로 친다**
- ⑤ 경우 항목의 `body`(제목행 아래 자기 본문)도 경우 클릭으로 열리므로 제외

⚠ 같은 계산을 heading 섹션에는 **적용하지 않는다** — 제목은 원래 표시되는 내용이라 여닫이를 없앨 수 없고, "펼쳐도 변화 없음"은 톤 변화(S3)가 이미 상태를 말해 준다.
테스트: `test:case`(41건)에 ① 첫 블록이 pinned일 때 전문 여닫이 없음 ② 그 앞에 일반 텍스트가 하나라도 있으면 있음 ③ 레거시 라벨 블록 → 있음 ④ 경우로만 시작 → 없음.

### A3 — OCR 버튼 이동: 목표 구조가 이미 절반 있다

## 5. B2 — 번분수 가로바·세로 여백 (방향 확정, 정의는 Q1)

별첨 목업은 **이미 두 판을 비교하고 있다** — "V1 (CSS만): 세로 여백 없음" vs "V1 + 세로 여백 매크로: 가로바 위아래 최소 간격 확보". 즉 어딘가(웹 대화로 추정)에서 프로토타입이 한 번 만들어졌다. **그 정의(CSS 규칙·매크로 원문)를 v2에서 공급해 달라(Q1)** — 이 계획서가 재발명하는 것은 낭비고, 재발명하면 목업과 미묘하게 다른 판이 하나 더 생긴다.

v1이 확정하는 것은 **주입 지점과 제약**이다:

- KaTeX 옵션 주입구는 **사본 2곳**: `EditorPreview.tsx:316` · `PrintableContent.tsx:137` — 이미 `macros: { "\\arraystretch": "1.8" }` 전례가 있다(같은 값을 두 곳에 적는 구조). 매크로를 더하면 **두 곳을 함께** 고친다. ⚠ 검증 카드의 `renderInlineMathHtml`(katex-render.ts)은 인라인 전용이라 대상 아님 — v2에서 반박 가능.
- CSS 쪽이면 `.preview-content`(화면, globals.css) + `.print-body`(인쇄, PrintStyles.css) **양쪽 스코프** — PrintStyles는 앱 전 화면에 로드되므로 접두 필수(기존 규약).
- ⚠ `\frac` 재정의 매크로는 **모든 수식**에 걸린다 — 중첩 아닌 평범한 분수·인라인 `$\frac{1}{2}$`의 조판이 변하지 않는지가 검수 관문이다. 인라인까지 바뀌면 본문 줄 높이가 흔들린다(목업 마지막 줄 "본문 인라인"이 정확히 이 검증용으로 보인다).
- 검수는 목업의 표본 6종을 실물 문항으로 재현 + **인쇄 PDF 대조**(화면·인쇄가 같은 매크로를 받는지).
