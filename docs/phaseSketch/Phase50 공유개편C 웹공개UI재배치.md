# Phase 50 — 공유 기능 확장개편 (C) : 웹에 공개 UI 재배치

> **공유 개편 3부작 중 3부.** Phase 48(A)·49(B) 배포 후 진행.
> 웹 공개의 **데이터 계층은 이미 완성**(`lib/shares.ts`, `shares/{shareId}` 스냅샷 모델, `app/shared/[shareId]`). 이 단계는 **UI 재배치 + 만료 정책 조정**이 핵심이다.

## 0. 선행 확인 (구현 전 반드시 읽을 것)

- `lib/shares.ts` — `DEFAULT_EXPIRY_HOURS`(현재 72), `MAX_EXPIRY_DAYS`(현재 30), shareId 생성, `ShareSnapshot`, share 생성/조회/삭제, `where(ownerUid==uid)` listing 유무
- `app/shared/[shareId]/page.tsx` — 비로그인 뷰어, 만료 처리
- `firestore.rules` — `shares` 규칙(read: any / create·delete: owner / update: false)
- Phase 49에서 만든 `ListView` 컴포넌트 — 웹 컬럼셋 추가 대상
- `components/editor/SharePanel.tsx` — (B에서 제거됐다면) 웹 공개 생성 로직만 재사용 참고

## 1. 목표 (결정 반영)

1. `공유 > 공유 보낸 > 웹에 공개` 노드의 콘텐츠를 **리스트**로 표시.
2. **만료 칩 3 / 7 / 30 / 무기한, 기본값 무기한.**
3. 링크 복사 · 공개 중단(revoke).
4. My 문항을 **웹에 공개로 거는 경로**(버튼/DnD) 제공.
5. 공유 탭은 **생성 시 스냅샷**이라 사후 변경 불가 → 읽기전용 + 재공개 안내.

## 2. 만료 정책 조정 (`lib/shares.ts`)

```ts
// 기본값을 무기한으로
export const DEFAULT_EXPIRY: number | null = null;   // null = 무기한
export const EXPIRY_PRESETS = [3, 7, 30, null] as const; // 일 단위, null=무기한
```
- 기존 `DEFAULT_EXPIRY_HOURS=72`를 기본 무기한으로 교체. 단 **무기한 허용은 이미 모델에 있음**(`Share.expiresAt: Date | null`).
- `MAX_EXPIRY_DAYS=30`은 프리셋 상한과 일치 — 유지.
- 만료일 계산: 게시 시점 + N일. 무기한은 `expiresAt = null`.

> **공유 문서는 update 불가(규칙)**. 만료일 변경은 **revoke + 재발급**(delete 후 create)으로 처리. 이때 **shareId가 바뀌어 기존 링크가 죽는다** → UI에서 "만료일을 바꾸면 링크가 새로 발급됩니다" 경고. 만료 칩 변경 = 재발급으로 명시.

## 3. 웹에 공개 — 리스트 컬럼셋 (ListView 확장)

| 컬럼 | 동작 |
|---|---|
| 제목 (클릭) | 비로그인 뷰어(`/shared/{shareId}`) 새 탭 |
| 게시일 | `share.createdAt` |
| 블록체인 배지 | `problem.blockchain` 유무(스냅샷에 포함 시) |
| 공유 탭 | **읽기전용**(스냅샷 `tabVisibility`). 변경하려면 재공개 |
| 만료 | **편집 칩** 3/7/30/무기한 → 변경 시 revoke+재발급 경고 |
| 링크 복사 | `navigator.clipboard.writeText(원본 URL)` + 토스트 |
| 공개 중단 | `revoke`(share 문서 delete). 확인 다이얼로그 |

- 댓글 배지 없음(웹 스냅샷엔 댓글 채널 없음 — 결정 #5: 웹 공개 댓글은 *멤버 공유 한정*).
- 메타 컬럼 없음(B와 동일 원칙).

## 4. My → 웹에 공개로 거는 경로

- My 카드/리스트 행의 **"공유" 모달**(B의 `ShareTargetModal`)에 **탭 추가** 또는 별도 진입점으로 "웹에 공개" 옵션 제공:
  - 공유 탭 선택(스냅샷에 담을 탭) → 만료 선택(기본 무기한) → `createShare(problemId, { tabVisibility, expiresAt })` → shareId 반환 → 링크 즉시 복사 제공.
- (선택) DnD: My 문항을 `웹에 공개` 노드로 드롭 → 동일 생성 플로우. B의 결론대로 **모달 우선, DnD 후순위.**
- 한 문항당 **활성 링크 1건** 정책 유지 — 이미 공개 중이면 "이미 공개됨, 링크 보기/만료 변경" 제시.

## 5. 만료 차단의 한계 (정직하게 명시)

현재 만료 차단은 **뷰어 페이지의 클라이언트 `expiresAt` 검사 + 소유자 revoke**에 의존한다. 즉 만료된 링크라도 share 문서 자체가 남아 있으면 비로그인 단일 읽기는 가능(문서를 직접 때릴 경우). 진짜 차단은 다음 중 하나가 필요하나 **이번 범위 밖**으로 둔다:
- (후속) 스케줄드 Cloud Function으로 만료 share 자동 삭제, 또는
- (후속) 뷰어를 서버 라우트(SSR)로 바꿔 만료를 서버에서 강제.

이번 C에서는 뷰어 페이지가 만료 시 **"공유가 종료되었습니다"** 안내를 확실히 띄우는 것까지 보장(기존 처리 점검·보강).

## 6. 리스크 & 주의사항
- **revoke+재발급으로 링크가 바뀜**: 사용자가 이미 배포한 링크가 죽을 수 있음 → 만료 변경 UI에 강한 경고. "만료만 끄고 싶다"는 흔한 요구이므로, 무기한↔기한 전환도 재발급임을 분명히.
- **스냅샷 신선도**: 웹 공개는 생성 시점 스냅샷. 원문을 고쳐도 공개본은 안 바뀜(의도된 동작). 리스트에 "게시일" 노출로 사용자가 인지하게 함. 최신 반영이 필요하면 재공개.
- **clipboard API**는 https/사용자 제스처 컨텍스트 필요 — 버튼 클릭 핸들러 내에서 호출.
- **shares 규칙 변경 불필요**: create/delete만으로 모든 플로우 충족(update:false 유지).

- [ ] 링크 복사 버튼이 원본 URL을 클립보드에 복사

- [ ] `npm run build` 통과 + 기존 멤버/댓글 회귀 없음

**확정된 설계 결정**
- 탭 가시성: **전역**(`memberTabVisibility`, 문항당 1개). 사람별 미적용.
- 권한(보기/댓글): **사람별**(`members[uid]`), 기본 댓글.
- 대화명: **전역 유일 강제**.
- 웹 공개 댓글: **불가**(댓글은 멤버 공유 한정, 로그인 회원).
- 받은 문항: 사본/삭제 없음, **공유 나가기**만.
- 리스트 보기: **메타 컬럼 없음**, 댓글 배지 = **댓글 스트림 수**.
- DnD: **모달(버튼) 경로 우선**, 교차영역 DnD는 후순위/선택.
- **댓글 / agent 분리(Phase 46):** 댓글=사람 전용·전 접속자(오너가 가시성·쓰기 토글), agent=오너 전용 AI. 다자 사람+AI 토론 폐기.
- **댓글 쓰기(결정 A):** `역할 'commenter'` AND `commentsWritable`. 오너는 항상 가능.
