# Phase 61 기획서 — 스프레드시트 연동 · 정밀 검증 시스템 이식 (v2)

> 작성일: 2026-08-21 · v2: 덕수 결정사항(E-1~E-6) + 추가사항1(원본 시트 선택) + 추가사항2(사전 선별·폴더 선택) 반영
> 이 문서는 **무엇을, 왜 만드는지**를 정리한 기획서입니다. 기술 구현 방법은 2단계 문서(구현 계획서)에서 다룹니다.
> Phase 번호(61)는 임시이며, roadmap 상황에 맞게 조정 가능합니다.

## 0. 배경과 전체 그림

### 지금의 상황

- **스프레드시트 + gas-project-audition**: 대량의 문항을 시트에 쌓아 놓고, AI(Gemini + Claude 교차검증)로 문제·해설 오류를 일괄 검증하는 시스템. 잘 작동하고 있고 앞으로도 계속 발전시킬 예정.
- **Mathory**: 문항을 블록 단위로 편집·관리·인쇄하는 플랫폼. AI 기능(agent 대화, 교정, OCR)이 이미 들어 있음.
- 두 시스템은 현재 **서로 연결되어 있지 않음**. 시트에서 검증을 마친 문항을 Mathory로 옮기려면 손으로 복사해야 하고, Mathory 안에서 문항을 다듬은 뒤에는 오류 검증을 다시 할 방법이 없음.

### 만들려는 것 — 세 개의 축

| 축 | 이름 | 한 줄 요약 |
|---|---|---|
| A | 문항 가져오기 | 시트의 문항을 행 범위로 지정해 Mathory의 새 폴더로 한 번에 가져온다 |
| B | 정밀 검증 | Mathory 안에서 문항 하나를 골라 문제·풀이 오류를 깊게 검증한다 (agent 대화창에 통합) |
| C | 대화 → 편집창 삽입 | agent 대화에서 얻은 구절·수식을 드래그해서 편집창에 바로 꽂는다 |

**진행 순서는 A(가져오기)부터.** (E-6 결정)

### 역할 분담의 철학

- **시트 = 대량 검증 공장.** 수백 문항을 돌려서 "어느 문항이 의심스러운지" 걸러내는 곳.
- **Mathory = 정밀 검증 작업실.** 한 문항을 붙잡고 "정확히 어디가 왜 틀렸는지" 파고들어, 그 자리에서 바로 고치는 곳.
- 두 시스템은 코드가 아니라 **자산(프롬프트, 판정 기준, 검증 정책)** 을 공유한다. 한쪽에서 프롬프트를 개선하면 다른 쪽도 같이 좋아지는 구조. (→ B-7)

## A. 문항 가져오기 (시트 → Mathory)

### A-1. 목표

시트에 쌓인 검증 완료 문항들을, 손 복사 없이 Mathory의 새 문항 폴더로 옮긴다. "시트 고르고 행 범위만 입력하면 끝"이 목표.

**원본 시트는 두 곳** (추가사항1): 같은 스프레드시트 안에 동일한 구조의 시트가 두 개 있다 —

- **Data_DS**: 가장 최근에 검사한 세트 (통상 50문항 이하)
- **Stack**: 최근 세트를 제외한, 지금까지 검사한 모든 세트의 누적

### A-2. 사용자 시나리오 (덕수의 화면에서 벌어지는 일)

1. Mathory에서 "시트에서 가져오기" 화면을 연다.
2. **원본 시트를 선택한다: Data_DS(최근 세트) 또는 Stack(누적).** (추가사항1 — 프로세스 맨 앞)
3. 행 범위 입력 팝업에서 가져올 문항을 지정한다. (추가사항2)
   - 행 범위 입력: 예: `15-32` 또는 `15, 17, 20-25` (시트에서 쓰던 입력 방식 그대로)
   - 팝업 안의 체크박스: **[사전 선별(M열 체크 표시) 된 문제 포함하기]**
   - **행 범위를 비워 두면 사전 선별 문제만** 가져온다. (행 범위와 체크박스를 함께 쓰면 둘의 합집합)
4. **폴더를 선택한다.** (추가사항2) 클릭하면 폴더 탐색창이 뜨고, Mathory **My의 전체 폴더 체계**에서 원하는 폴더를 고른다. 하단의 **[폴더 새로 만들기]** 버튼을 누르면 탐색기의 현재 폴더 아래에 하위 폴더가 생성된다.
5. Mathory가 시트를 읽어 와서 **미리보기**를 보여준다 — 각 행이 문제/풀이/AI풀이로 어떻게 나뉘었고, 수식이 제대로 렌더되는지 눈으로 확인.
6. "가져오기"를 누르면 선택한 폴더에 문항들이 저장된다. **각 문항의 제목은 A열(id) 내용 그대로.** (E-3 결정)
7. 이미 가져온 행을 다시 지정하면 "이 행은 이미 가져왔습니다"라고 알려 준다.

시트 쪽에서는 **아무것도 하지 않아도 된다.** 메뉴 추가도, 내보내기 버튼도 없음. (Mathory가 시트를 직접 읽는 B안 채택)

### A-3. 가져오는 정보 (열 매핑) — 확정 (E-1·E-2, 시트설명.xlsx 기준)

**가져오는 열 (O)**

| 시트 열 | 내용 | Mathory에서의 자리 |
|---|---|---|
| A (id) | 세트명·과목·번호 | **문항 제목** (그대로) |
| C (given_solution) | 해설 | **"풀이" 탭** — 블록1 (텍스트) |
| D (given_answer) | 공식 정답 | **정답 필드** |
| E (problem_stem) | 문제 본문 | **"문제" 탭** — 블록1 (텍스트) |
| F~J (choice1~5) | 선택지 ①~⑤ | **"문제" 탭** — 블록2 (**선택지 블록**) |
| O (derived_answer) | AI가 구한 정답 | **"AI풀이" 탭(새로 생성)** — 블록1 (텍스트) |
| P (solution_note) | AI가 쓴 풀이 | **"AI풀이" 탭(새로 생성)** — 블록2 (텍스트) |

**가져오지 않는 열 (X)**: B(문제 전체 원본), K(answer_type), L(빈 열), N·Q·R·S·T·U~X(시트 검증 결과·통계) — 검증 결과는 시트에서 관리하고, Mathory는 자체 정밀 검증(B축)으로 새로 판정한다.

**선별용으로만 읽는 열**: **M (get, 체크박스)** — 문항 내용으로 가져오지는 않고, "사전 선별 문제만 가져오기"(A-2의 3번)의 필터 기준으로 사용한다. Data_DS·Stack 두 시트 모두에 있다. (추가사항2)

참고:

- 선택지는 Mathory에 이미 있는 **선택지 블록** 형식을 그대로 사용한다. 단답형 문항(선택지 F~J가 빈 행)은 선택지 블록 없이 문제 블록만 만든다.
- "AI풀이" 탭은 Mathory의 동적 탭 기능으로 생성한다. O·P가 모두 빈 행은 AI풀이 탭을 만들지 않는다.
- 시트는 **읽기만** 한다. 가져오기가 시트 내용을 바꾸는 일은 없다.
- 열 위치가 아니라 **1행 헤더 이름으로** 읽으므로, 앞으로 시트에 열을 추가해도 가져오기가 어긋나지 않는다.

### A-4. 변환 규칙

시트의 문제·풀이 텍스트를 Mathory의 표기 규약(수식 `$...$`, (가)·ㄱ.·① 마커 등)에 맞게 다듬는 규칙. 수식 표기는 이미 양쪽이 같은 방식이라 큰 산은 없을 것으로 예상.

- 규칙은 책상에서 확정하지 않고, **실제 5~10행으로 파일럿 가져오기**를 돌려 미리보기로 깨지는 곳을 보면서 확정한다.
- 텍스트 블록의 추가 분할은 하지 않는다. 위 매핑표의 블록 구성(문제=텍스트+선택지, 풀이=텍스트 1개, AI풀이=텍스트 2개)만 만들고, 다듬기는 Mathory 편집창에서.

### A-5. 안전장치

- **미리보기 필수**: 저장 전에 반드시 변환 결과를 눈으로 확인하는 단계를 거친다.
- **중복 방지**: 각 문항에 "어느 시트의 몇 행에서 언제 가져왔는지"를 기록한다. 다만 세트가 나중에 Data_DS → Stack으로 이동하면 행 번호가 달라지므로, **중복 판정의 기준은 행 번호가 아니라 A열 id**로 한다(같은 id의 문항이 이미 있으면 알려 주고, 원하면 덮어쓰기 선택 가능).
- **실패 행 처리**: 일부 행이 변환에 실패해도 나머지는 가져와지고, 실패한 행 번호와 이유가 표시된다.

## B. 정밀 검증 (agent 대화창에 통합)

### B-1. 목표와 철학

문항 하나를 열고, 버튼 한 번으로 문제·풀이의 오류를 깊게 검증한다. 결과는 점수표가 아니라 **대화의 시작점**이다.

- **"버튼으로 시작하고, 대화로 이어진다."** 검증 실행은 버튼(정해진 절차)으로, 결과에 대한 추궁은 대화로. "2번 지적이 정말 맞아? 반례 들어봐"라고 이어서 따질 수 있는 것이 시트 일괄 검증과의 결정적 차이.
- 새 화면을 만들지 않는다. **기존 agent 대화창 안에** 녹인다. AI 기능의 입구가 하나로 유지된다.

### B-2. 실행 단위 — 버튼은 두 개만

agent 입력창 위에 선택 칩(버튼) 두 개를 둔다:

- **[문제 검증]** — 문제 자체의 결함 검사
- **[풀이 검증]** — 풀이의 계산·표기·논리 오류 검사

**비용 확인 관문 (E-5 결정)**: 검증 버튼을 클릭하면 "이 검증은 API 비용이 발생합니다" 확인 팝업을 띄우고, 확인을 눌러야 실행된다. (실수 클릭으로 비용이 새는 것 방지)

기존 **교정(proofread)** 기능은 그대로 별도 유지한다(맞춤법·띄어쓰기·LaTeX 문법 같은 표면 검사). 오류의 세부 분류는 버튼을 늘리는 방식이 아니라, 결과 리포트 안에서 태그로 구분한다(→ B-3). 버튼은 단순하게, 분류는 정밀하게.

### B-3. 오류 분류 체계 — 확정 (E-4: 전체 수용)

각 지적(finding)에는 종류 태그가 붙는다:

**문제 검증에서 나오는 태그**

| 태그 | 뜻 | 예 |
|---|---|---|
| 조건 결함 | 조건 상충·누락으로 문제가 성립하지 않음 | 답이 존재하지 않는 조건 조합 |
| 답 유일성 | 답이 하나로 확정되지 않음 | 숨은 조건 없이는 답이 2개 |
| 선택지 오류 | 정답이 선택지에 없음, 선택지 중복 등 | 계산하면 답이 7인데 선택지에 없음 |
| 표기 | 문제 쪽 수학적 표기 오류 | 기호 오용, 정의역 누락 |

**풀이 검증에서 나오는 태그**

| 태그 | 뜻 | 예 |
|---|---|---|
| 계산 오류 | 식 변형·수치 계산이 틀림 (기계 검산으로 확정) | 적분 계산 실수 |
| 표기 오류 | 수학적 표기가 틀리거나 오해를 부름 | =와 ⇒ 혼용, 변수 충돌 |
| 논리 비약 | 근거 제시 없이 건너뜀 (틀린 건 아님) | "따라서"로 넘어가는데 중간 단계 누락 |
| 논리 오류 | 추론 자체가 틀림 | 역이 성립한다고 가정 |
| 서술 비일관 | 앞뒤 서술이 어긋남 | 앞에서 정의한 기호를 다른 뜻으로 사용 |
| 경우 누락 | 경우 나누기에서 한 경우를 빠뜨림 | 음수인 경우 미검토 |
| 문제-풀이 불일치 | 문제에 없는 조건을 가정, 조건 오독 | 문제는 실수 범위인데 풀이는 자연수로 가정 |

**공통(양쪽에서 나올 수 있는 태그)**

| 태그 | 뜻 |
|---|---|
| 정답 불일치 | **삼자 대조** 결과가 어긋남: ① AI가 문제를 독립적으로 풀어 도출한 답 ↔ ② 풀이의 결론 ↔ ③ 문항에 등록된 정답(D열에서 가져온 값). 어느 둘이 어긋나느냐로 원인(문제 결함/풀이 오류/정답 입력 실수)을 진단 |

### B-4. 검증 엔진 — 기존 시스템에서 계승하는 것

시트 시스템에서 검증된 방법론을 그대로 가져온다:

- **교차검증**: 1차 Gemini가 의심 지점 후보를 폭넓게 찾고(놓치지 않기), 2차 Claude가 후보를 엄격하게 판정한다(오판 줄이기). 시트 STEP3에서 효과가 확인된 비대칭 구조.
- **보수적 판정 철학**: 확신이 없으면 "오류"가 아니라 "확인 필요(check)"로 판정. AI가 못 풀었다는 이유만으로 문제를 결함으로 몰지 않는다.
- **판정 어휘**: ok(통과) / check(확인 필요) / fail(확정 결함) / skip(검증 불가) — 시트와 동일한 어휘 유지.

Mathory여서 새로 가능해지는 것:

- **기계 검산**: 계산 오류는 AI의 "말"이 아니라 실제 수식 계산 실행(SymPy)으로 확정한다. Mathory의 AI 기반에 이미 있는 기능을 검증에 연결.
- **블록 앵커링**: 지적이 "풀이 3번째 블록의 이 부분"처럼 특정 블록을 가리키고, 클릭하면 그 블록으로 이동한다.

### B-5. 결과 표시 — 검증 리포트 카드

검증이 끝나면 agent 대화 스레드에 일반 채팅 메시지가 아닌 **리포트 카드**가 꽂힌다:

- 맨 위: 종합 판정 배지 (ok / check / fail / skip)
- 지적 목록: 태그 + 해당 구절 + 무엇이 왜 문제인지 + (가능하면) 수정 제안
- 각 지적 클릭 → 해당 블록으로 점프
- 카드 아래부터는 자유 대화 — 지적에 대해 되묻고, 반박하고, 고친 뒤 재검증

### B-6. 검증 상태 관리

- 문항마다 최근 검증 결과가 저장되고, 문항 목록에서 배지로 보인다: ✓(통과) / △(확인 필요) / ✗(결함) / (미검증)
- **문항을 편집하면 "재검증 필요" 상태로 자동 전환** — 검증 당시의 내용과 지금 내용이 달라졌음을 시스템이 안다.
- 폴더를 열면 어떤 문항이 아직 검증 안 됐는지 한눈에 파악 가능. (대량 실행은 시트의 몫이지만, 커버리지 관리는 Mathory 안에서도 된다)

### B-7. 기존 시트 시스템과의 관계 — 공유 자산 3종

코드는 공유할 수 없다(환경이 다름). 대신 다음 세 가지를 **공유 자산**으로 한 곳에 정리해 두고 양쪽이 같은 원본을 쓴다:

1. **프롬프트 세트** (시트의 pmt에 해당)
2. **판정 어휘와 리포트 형식** (ok/check/fail/skip, 지적 태그 체계)
3. **교차검증 정책** (어떤 모델이 1차·2차인지, 후보 상한 등)

운용: 원본은 Mathory 저장소에 두고, 시트의 pmt는 원본에서 복사해 넣는다. 프롬프트를 개선하면 양쪽이 함께 좋아진다.

### B-8. 한계 (미리 정해두는 것)

- **그림(이미지)에 의존하는 문항**: 그림 없이 검증이 불가능하면 skip으로 판정하고 이유를 남긴다. (그림 이해 검증은 이번 범위에서 제외)
- 검증은 **오류 탐지**까지다. "더 좋은 풀이 제안" 같은 품질 평가는 이번 범위가 아님 (원하면 후속 Phase).

## C. 대화 → 편집창 삽입

### C-1. 목표

agent 대화(특히 검증 리포트와 후속 대화)에서 얻은 유용한 구절·수식을, 복사-붙여넣기 없이 편집창의 커서 위치에 바로 꽂는다.

### C-2. 동작

1. agent 창에서 원하는 영역을 드래그하면, 선택 영역 근처에 미니 팝업이 뜬다: **[편집창에 삽입]** (+ 보조로 [복사])
2. 삽입을 누르면 현재 활성 블록의 커서 위치에 그 내용이 들어간다.
3. 화면에 예쁘게 렌더된 수식도, 삽입되는 순간 **원본 LaTeX(`$...$`)로 정확히 복원**된다 — 렌더된 수식 안에 원본이 보존되어 있어 추측 변환이 아니라 무손실 복원이다.

### C-3. 규칙

- 드래그가 수식 중간을 걸치면 그 수식은 통째로 포함 (수식은 자르지 않는다)
- 인라인 수식(`$`)과 별행 수식(`$$`) 구분 유지, 문단 경계는 빈 줄로
- AI가 가끔 쓰는 다른 수식 표기(`\(...\)`)도 Mathory 규약(`$...$`)으로 통일해서 삽입

## D. 진행 순서 — 확정 (E-6: A 먼저)

한 번에 다 만들지 않고, 각 단계가 그 자체로 쓸모 있도록 나눈다:

| 단계 | 내용 | 완료 시 얻는 것 |
|---|---|---|
| 1 | **가져오기**: 변환 규칙 파일럿 + 가져오기 화면 | 시트 문항이 Mathory에 들어온다 |
| 2 | 검증 코어: 프롬프트·판정 체계 정리 + 문제/풀이 검증 실행 | 문항 하나를 검증할 수 있다 (결과는 우선 단순 표시) |
| 3 | agent 통합: 검증 칩(+비용 확인 팝업) + 리포트 카드 + 블록 점프 + 후속 대화 | 검증이 대화형 워크플로우가 된다 |
| 4 | 상태 관리: 검증 배지 + 편집 시 재검증 필요 | 폴더 단위 커버리지 관리 |
| 5 | 삽입 기능: 드래그 → 편집창 삽입 | 대화 결과를 편집으로 연결 |

각 단계 완료마다 기존 방식대로 Phase 문서(v1 → 교차검토 → 최종)로 관리.
