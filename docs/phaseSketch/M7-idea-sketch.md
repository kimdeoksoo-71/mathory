* inline 수식 구분자 $$ 입력 기능 보완  
  * 현재 문제점 : $$를 입력하면&nbsp;  
    * $$ 가 입력되면 displaystyle 수식기호 $$ … $$와 구별되지 않아 현재 입력 위치의 뒤에 있는  $$ … $$를 오류로 인식하여, 편집창에서 오류 인식 표시가 뜬다.  
    * 바로 뒤에 수식 기호가 있으면 $$$...$ 가 되어 $$$ 를 수식으로 인식하지 못한다.  
  * 다음의 해결책이 적절한지 검토바람  
    * 수식입력 버튼, 단축키 (키보드에서 $를 개별적으로 입력하는 것은 제외)에 의해 입력되는  inline 수식구분자를 기존의 ‘$$’ 에서 ‘$ $ ’로 대체한다.  
    * 편집창에서 실험한 결과 앞서 말한 현재의 문제점 2가지는 사라지는것으로 보임  
    * 대체했을때 발생할 수 있는 문제점은 없는지 면밀하게 검토하여  
      * 심각한 문제점이 있으면 : 대체안을 제시  
      * 심각한 문제점이 없으면 : 제시한 안으로 수정보완

* EditorView 편집창 커서 위치에 따른 자동 좌우 스크롤 기능  
  * 현재 문제점 : 줄바꿈(opt+z)을 끈 상태에서 키보드 타이핑으로 입력하면 커서가 오른쪽 경계선 끝에 다다랐을 때 한 자 한자 입력함에 따라 화면이 한칸씩 오른쪽으로 이동한다. 시각적, 심리적 압박감에 따른 불편감이 있음.  
  * 좌우 자동스크롤 기능 도입 타당성 검토  
    * 제안 : 복사한 텍스트 덩어리를 붙여넣기로 한꺼번에 넣는것이 아닌, 키보드 입력에 따라 커서 위치가 오른쪽 끝 경계선에 다다르면 자동으로 좌우스크롤이 되어 커서 위치가 입력창의 가로 중앙에 오도록 빠르게 스크롤된다.  
    * 제안한 자동 좌우스크롤 기능을 도입의 타당성을 검토하고, 타당하다면 도입.

* EditorView 우측 패널 펼침시 탭버튼, 저장버튼만 보이도록 기능 조정  
  * 현재 문제점 : ai agent 우측 패널을 펼치고 작업을 할때 패널창이 각종 버튼을 덮어버려서 편집작업에 불편함이 드러났음. 주요 불편은  
    * 탭 전환이 안된다.  
    * 저장이 안된다.&nbsp;  
  * 애초 우측 패널(드로어)가 기존의 화면을 덮도록 기능을 조정한 것은 좁은 화면에서 버튼이 드로어에 밀려 왼쪽으로 이동함에 따라 EditorView 1행, 2행이 번잡해지는 것이 보기에 불편해서였음.  
  * 개선 방향 : EditorView에서 우측 드로어가 펼쳐지면 다음 두개의 버튼은 드로어의 왼쪽으로 밀려나도록 하고, 스탭퍼와 다른 버튼들은 기존의 방식대로 우측 드로어에 의해 덮이도록 한다.  
    * 1행의 저장버튼  
    * 2행의 탭버튼들  
  * 화면폭이 좁아서 1행, 2행에 각 행의 내용이 넘치면  
    * 행 안에서 내용을 2줄 이상으로 만들지 않는다.  
    * 2행에서는 탭버튼이 왼쪽의 툴바 내용을 덮고, 1행에서는 저장버튼이 왼쪽 문항명, 폴더명을 덮는다.

*  편집중인 문항 30분마다 자동 저장 기능 도입  
  * 긴 시간 한 문제를 편집하다 보면 저장을 잊고 문제에 몰두하게 된다.&nbsp;  
  * 이때, 저장을 잊고 화면을 끄면 몇시간을 작업한 것이 지워지는 경우가 있음.  
  * 한 문항의 편집화면에 30분이 이상 머무르면 현재 작업중인 문항을 30분에 한 번씩 자동저장하는 기능 도입한다.

* EditorView 에서 블록 복사, 붙여넣기 기능 도입  
  * 취지 : 블록 또는 블록들 여러개를 복사해 다른 탭에 붙여넣기 위함. 현재는 블록 안으로 들어가서 내용을 복사한 뒤 탭을 옮기고, 블록을 만들고, 블록 속성을 지정한 뒤에 붙여넣기를 각 블록 마다 반복해야 해서 불편함.&nbsp;  
  * 편집화면에서 블록(들)을 복사, 붙여넣는 기능  
  * 블록(들)을 복사하여 다른 현재 탭의 원하는 위치에 붙여 넣을 수도 있게 하고,  
  * 블록(들)을 복사하여 다른 탭의 원하는 위치에 붙여 넣을수도 있게 한다.&nbsp;  
  * 붙여넣기 기능은 모든 블록들이 ‘접힘’ 상태에서만 가능하도록 한다.  
  * 붙여넣는 위치는 현재 선택된 블록의 바로 아래에,&nbsp;  
  * 현재 선택된 블록이 여러개이거나 선택된 블록이 없을 때 붙여넣기를 실행하면 ‘블록을 붙여 넣을 위치를 선택해 주세요’라는 안내 메시지를 띄운다.

* 블록 정돈 기능 도입  
  * 취지 : 시트 불러오기 또는 OCR 인식으로 불러온 문서들을 Mathory의 편집 체계에 맞게 블록을 분할하고, 가능한 경우 블록 형식을 부여한다.  
  * 작동방식  
    * 시트 불러오기로 여러개의 문항을 일괄 불러올때 : 불러올 때 자동으로 실행  
    * 개별 문항에 대해 EditorView에서 작동 : 별도 버튼 신설  
    * 버튼 아이콘은 phosphor : broom  
  * 기능  
    * 행이 여러개인 displaystyle 수식 덩어리는 각각을 별도의 블록으로 분리  
      * \\begint{}…\\end{}로 만들어지는 다중행 수식 덩어리  
        *  {aligned}, {case}, {array}  
      * displaystyle 수식이더라도 1행으로 이루어진 것은 별도 블록으로 분리하지 않는다.  
    * 경우 나눔 문단의 제목행을 ‘경우’ 또는 ‘하위 경우’ 블록으로 분할  
      * (i), (ii), (iii),  … 으로 시작하여 ‘인 경우’로 끝나는 문장  
        * 예 : (iii) $\\lim \_{x \\rightarrow-\\infty} f(x)=\\infty, \~ \\lim \_{x \\rightarrow \\infty} f(x)=-\\infty$ 인 경우&nbsp;  
      * (i), (ii), (iii), … 의 괄호 로마숫자를 삭제하고 ‘…인 경우’ 까지를 하나의 문장으로 분리하여 이 문장만을 별도의 ‘경우 블록’으로 만들어 준다.  
      * (i-1), (i-2), … 으로 시작하여 ‘인 경우’로 끝나는 문장 : 위와 마찬가지의 방법으로 괄호 로마숫자를 삭제하고 ‘…인 경우’ 까지를 하나의 문장으로 분리하여 이 문장만을 별도의 ‘하위 경우 블록’으로 만들어 준다.  
    * ‘\[참고\]’ 로 시작하는 행은 그 행을 별도의 제목 블록으로 분리  
    * STEP1, STEP2, … 로 시작하는 행은 그 행을 별도 제목 블록으로 분리  
      * 예 : “STEP3 주어진 조건을 만족시키는 모든 정수 $a$의 값 구하기”  
    * 풀이 첫머리의 불필요한 문제번호와 정답표시 제거  
      * 제거 대상  
        * 풀이 탭 첫행의 문제 번호 : 숫자+마침표&nbsp;  
          * 예 : 15\. , 7\. , 30\.&nbsp;  
        * 풀이 탭 2행 이하의 정답 표시 : ‘정답 \+ 원문자 숫자’ 또는 ‘정답 \+ 3자리 이항의 정수’&nbsp;  
          * 예 : 정답 ③, 정답 56  
  * 기존 proofread 기능에서 이전  
    * 기존 proofread에서 문법 및 내용 검토가 아닌 ‘편집 스타일’ 관련 정돈 기능은 블록 정돈기능으로 이전하고 proofread는 내용 검토에 국한, 집중한다.  
    * 이전할 기능의 목록을 작성하고 확인을 받는다.  
    * 이전할 기능 (생각나는 것만 우선 열거)  
      * 블록의 상단, 하단에 있는 불필요한 빈 줄 제거

* proofread에 기능 추가  
  * inline 수식이 \\Rightarrow로 사작하는 경우 text로 꺼내기  
    * ‘$\\Rightarrow  … $’ 를 ‘⇒ $ … $’ 로 : 수식의 \\Rightarrow 를 텍스트의 ⇒로 바꾸어 수식 밖으로 꺼낸다.&nbsp;  
    * \\Rightarrow가 수식 중간에 있는 경우 ($... \\Rightarrow …$)는  ⇒를 꺼지내 않는다 : 수식 중간에 있는 경우는 수식 전체의 구조가 무너질 수 있으므로 꺼내지 않는다.&nbsp;

* ai agent 대화, 문제검증, 풀이검증시 경우 블록, 하위 경우 블록을 지칭하는 C1, C2, C1a, C2a,...인식  
  * 경우블록, 하위 경우블록 명칭 C1, C2, C1a, C2a, … 가 랜더링된 화면에 나타나지만 해당 블록의 편집창에는 텍스트로 나타나지 않는다. 이 경우 그 블록의 아래에서 풀이 서술과정에 ‘C1, C2, C3 에 의하여’ , ‘C2 에서’ 등으로 이를 인용하는 구절이 등장하면 ai agent는 이를 인식하지 못하고 서술 오류로 판단한다. ai agent가 이러한 착오를 일으키지 않고 해당 블록 이후에 등장하는 블록 명칭을 블록 전체의 내용으로 이해할 수 있도록 하는 근본 다책이 필요함.  
  * 방안 : 블록 제목행에 C1, C2, … 하위 블록 제목행에 C1a … 의 블록 명칭을&nbsp;  
    * 경우 블록, 하위 경우 블록을 생성하면 첫 행 앞머리에 텍스트로 넣고,&nbsp;  
    * 편집시에 수정되지 않게한다. 사이사이에 경우블록이나 하위 경우 블록을 추가하면 명치이 자동으로 바뀌어야 하므로 사람이 그 명칭을 수정하지 못하도록 하는 조치  
  * 위 방안의 타당성을 검토하여 타당하면 수용하고, 타당하지 않으면 대안 수립
