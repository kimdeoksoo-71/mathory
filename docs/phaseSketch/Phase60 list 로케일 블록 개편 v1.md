## 2. P1 — 직접 입력 전환

### 2.1 프리셋 교체 (EditorView.tsx 108-109)

```ts
gana:  '(가) \n(나) \n(다) ',
roman: 'ㄱ. \nㄴ. \nㄷ. ',
```

레이블·드롭다운·TEXT_BASED/SPLITTABLE/BORDERED 집합은 전부 무변경(타입 키 `gana`·`roman` 불변 — 데이터·undo 경로 영향 0).

### 2.2 리터럴 마커 인식 (변환 사본 2곳)

기존 3단계(레거시 변환) 직후에 추가 — 레거시 패턴 `(a)`·`(i)`와 리터럴 패턴이 겹치지 않으므로 순서 민감성 없음. P2의 공백 소비를 여기 내장한다.

```ts
/** (가)~(마) 리터럴 — 행 시작: marker span. 행 중간은 이미 리터럴이므로 변환 불필요 */
function convertGanaLiteral(text: string): string {
  return text.replace(/^\((가|나|다|라|마)\)[ \t]*/gm,
    (_, ch) => `<span class="marker-gana">(${ch})</span>`);
}

/** ㄱ.~ㅁ. 리터럴 — 행 시작: marker span */
function convertGiyeokLiteral(text: string): string {
  return text.replace(/^([ㄱㄴㄷㄹㅁ])\.[ \t]*/gm,
    (_, ch) => `<span class="marker-giyeok">${ch}.</span>`);
}
```

- 범위는 레거시와 동일하게 **5개 제한**(가~마 / ㄱ~ㅁ) — 기존 매핑 테이블(GANA·GIYEOK)의 값 집합과 일치.
- `preprocessLocale`의 `locale !== 'ko'` 조기 반환 안쪽에 두어 ko 전용 유지(로케일 블록 철학 그대로).
- EditorPreview 인라인 사본에도 동일 regex를 4단계 직후에 추가.

### 2.3 `insertMarkerLineBreaks` 확장 (사본 2곳)

`isMarkerLine` 판정에 리터럴 패턴 2종 추가:

```ts
/^\s*\((가|나|다|라|마)\)/.test(line) ||
/^\s*[ㄱㄴㄷㄹㅁ]\./.test(line) ||
```

(EditorPreview 사본은 기존 관례대로 `line.trimStart()` + `^` 형태로 동일 취지 반영.) 이것으로 신규 프리셋의 연속 3행이 현행 (a) 프리셋과 똑같이 각각 독립 `<p>`가 되어 내어쓰기 CSS가 행마다 걸린다.

### 2.4 레거시 공존 (D5)

`convertAlphaList`·`convertRomanList`·행 중간 치환·GANA/GIYEOK 테이블 전부 유지. 기존 문항은 렌더 무변화(P2로 인한 간격 개선 제외 — §6 T3), 신규 문항은 변환 없이 리터럴이 그대로 흐른다. locale.ts 헤더 주석(1-8행)의 "저장: 국제 표준" 문구를 새 철학으로 갱신한다.

## 3. P2 — 마커 공백 정규화

### 3.1 regex 측 (사본 2곳)

- 신규 리터럴 변환은 §2.2에 내장 완료.
- **레거시 변환에도 동일 적용**: `convertAlphaList`·`convertRomanList`의 행 시작 패턴을 `^\(([a-e])\)[ \t]*` / `^\((iii|ii|iv|v|i)\)[ \t]*`로 — 기존 문서도 공백 유무와 무관해진다(의도된 개선, T3에서 확인).
- 행 중간 치환은 손대지 않는다(문장 속 인용은 공백이 유의미).

### 3.2 CSS 측 — 화면에 마커 고정폭 부여 (globals.css)

```css
/* 마커 고정폭 — 인쇄(PrintStyles 124)와 동형. 간격을 입력 공백이 아니라 CSS가 공급한다.
   text-indent: 0은 p:has 내어쓰기(-2.5em)가 inline-block 안쪽 첫 줄에 재적용되는 것을
   차단하는 가드 — .marker-circled(365-370)와 동일 선례. 굵기는 D8대로 현행 유지(부여 안 함). */
.marker-gana, .marker-giyeok {
  display: inline-block;
  text-indent: 0;
}
.marker-gana  { min-width: 2.5em; }  /* p:has(.marker-gana)의 내어쓰기 폭과 1:1 (D4) */
.marker-giyeok { min-width: 2em; }   /* p:has(.marker-giyeok) 2em과 1:1 (D4) */
```

인쇄는 regex가 공유 라이브러리라 공백 소비가 자동 반영되고, min-width는 이미 있으므로 **CSS 무변경**(giyeok 폭 통일은 Q2).

### 3.3 결과 표 (목표 동작)

| 입력 | 화면·인쇄 공통 렌더 |
|---|---|
| `(가)원이 삼각형에 내접하는 경우` | 마커 span(고정폭) + 본문 — 랩 라인과 정렬 |
| `(가) 원이 삼각형에 내접하는 경우` | **위와 완전 동일** (공백은 regex가 소비) |
| `(가)  내용` (공백 2개) | 위와 동일 (`[ \t]*`) |
| 행 중간 `…조건 (가)에 의해…` | 그대로 — 정규화 비대상 |

## 4. P3 — proofread 마스킹 확장 (lib/proofread.ts 59)

행 선두 마커 매칭에 리터럴 2종 추가:

```ts
const markerMatch = text.slice(i).match(
  /^(?:\(([a-z]+|[ivx]+)\)|\((?:가|나|다|라|마)\)|[ㄱㄴㄷㄹㅁ]\.)\s*/
);
```

기존 (a)/(i) 마스킹과 같은 placeholder 경로를 타므로 복원 로직 무변경. (여기는 행 단위 walk 내부라 기존 코드가 `\s*`를 쓰고 있고 라인 시작 판정이 별도로 있으므로 관례를 따르되, v2에서 `[ \t]*` 통일 여부만 확인.)
