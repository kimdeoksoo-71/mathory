## 1. 목표

1. **P1 (버그)** — 블록 삭제 완료 시 편집창이 현재 탭 **첫 번째 블록으로 자동 세로 스크롤**되는 오동작 제거. 연속 삭제 시 매번 되돌아와야 하는 불편 해소.
2. **P2 (접힘 바 버튼)** — 전체접기 모드의 접힌 상단바에 **'요약에 넣기' 스위치와 삭제 버튼**을 노출·작동시킨다.
3. **P3 (다중선택 보강)** — 접힘 상태에서 연속된 2개 이상 블록을 쉽게 선택·이동할 수 있게 한다(범위 선택 도입).
4. **P4 (선택 표시 통일)** — 접힘 상태의 선택 블록 표시를 현행 outline에서, 펼친 상태의 활성/비활성 구분과 동일한 **'바탕색 + 그림자'** 문법으로 통일.

## 2. 현행 실측 & 타당성 판정

### 2-1. P1 버그 — 원인 특정 (재현 경로 코드로 확인)

삭제 버튼은 **활성 블록의 펼친 상단바에만** 있으므로(823–838), 삭제되는 블록은 사실상 항상 활성 블록이다. 그때:

1. `handleDeleteBlock`(1543)이 `activeBlockId === blockId`이면 **`setActiveBlockId(filtered[0])`** — 남은 블록 중 **무조건 첫 번째**를 활성화한다 (1550).
2. `activeBlockId` 변경 → "블록 활성화 기본 자동 스크롤" effect(2179–2197)가 발동. 이 경로는 `skipNextBlockScrollRef`를 세우지 않으므로 skip되지 않고, **첫 블록 상단 −80px로 `fastScrollTo`** 실행.

→ 메모의 증상("삭제 후 현재 탭의 첫 번째 블록으로 스크롤")과 정확히 일치. **원인 2개가 중첩**: (a) 활성 승계 대상이 '이웃'이 아니라 '첫 블록', (b) 삭제로 인한 활성 전환에도 자동 스크롤이 발동. 둘 다 고쳐야 한다 — (a)만 고치면 이웃 블록으로의 미세 스크롤이 남고, (b)만 고치면 이후 다른 경로(툴바 게이팅·수식 클릭 등)가 엉뚱한 '첫 블록' 기준으로 동작한다.

**타당성: 상(소규모·국소 수정).** Phase 55a `pushUndo`가 삭제 직전 이미 연결돼 있어 undo 경로와의 충돌 없음.

### 2-2. P2 접힘 바 버튼 — 현행에 없음 확인

접힌 바 분기(780–790)는 grip + 타입 라벨 + 첫 줄 미리보기(flex:1)뿐. `summaryToggle`(706)과 삭제 버튼은 **펼친 분기(791–840)에만** 렌더된다. 접힌 바에 두 요소를 추가하는 것은 기존 부품 재사용이라 공수 작음.

주의점: 접힌 바는 (i) 클릭=선택, (ii) Shift+클릭=토글, (iii) 더블클릭=개별 펼침, (iv) grip 존 드래그가 겹치는 영역이다. 버튼들은 기존 관례대로 `onClick`/`onPointerDown` **stopPropagation**으로 격리(현행 summaryToggle·삭제 버튼 모두 이미 이 패턴, 707–708 / 825–826). 더블클릭 판정에 버튼 클릭이 섞이지 않는지 실측 필요(R2).

**타당성: 상.**

### 2-3. P3 다중선택 — ⚠️ 중요 실측 보고: "1개만 선택 가능"은 현행과 다름

메모의 현행 인식과 달리, **Phase 45에서 Shift+클릭 다중선택·묶음 이동이 이미 구현·배포돼 있다**(phasedocs Phase45 §4: Shift+클릭 토글, 연속·비연속 무관 묶음 재배치 `handleDragEnd` 1954–1995). 코드상 접기 모드에서도 상단바가 렌더되므로 동작 경로는 살아 있다.

다만 실사용에서 "안 된다"고 느껴질 만한 실제 문제 3가지를 확인:

1. **일반 클릭이 선택을 즉시 파괴 + 스크롤 유발** — `handleSelectBlockBar`(1934)는 `setSelectedBlockIds(new Set())`로 선택을 비우고, **collapseMode 가드 없이** `scrollEditorToBlockTop`/`scrollPreviewToBlockTop`을 직접 호출한다. Phase 45는 "접기 모드에선 활성화 자동 스크롤 비활성"(effect의 `collapseMode` skip)을 설계했지만, 이후 Phase 56에서 도입된 이 핸들러의 **직접 스크롤 경로가 가드를 우회**한다 — 접기 모드에서 바를 클릭할 때마다 목록이 튀는 회귀. 이것이 "이동이 번거롭다"는 체감의 유력한 원인.
2. **범위 선택 부재** — 연속 N개를 잡으려면 N번 Shift+클릭해야 한다. 메모의 "연속된 2개 이상 동시 선택" 요구의 실체는 **범위 선택(클릭=앵커, Shift+클릭=앵커→대상 연속 구간)**으로 해석된다.
3. **발견성 없음** — Shift+클릭을 안내하는 UI 단서가 전무(title 툴팁조차 없음).

**타당성: 상 (신규 개발이 아니라 보강).** 단, Shift 키의 의미를 '개별 토글'→'범위 선택'으로 바꾸면 Phase 45의 비연속 선택 기능이 갈 곳을 잃는다 → 키 배치는 Q2로 덕수 확정 필요.

### 2-4. P4 선택 표시 통일 — 현행 문법 정리

| 상태 | 현행 표시 |
|---|---|
| 펼친 활성 블록 | 래퍼 `background: --block-bg-active` + `boxShadow: --block-shadow-active` (692, 695) |
| 접힘 모드 선택 블록 | 래퍼 `outline: 2px solid --accent-primary` (696) — Phase 45 결정 |
| 접힘 모드 모든 바 | 배경이 **`--block-bg-active`로 하드코딩**(752) → 접기 모드에선 활성/비활성/선택이 배경으로는 전혀 구분되지 않음 |

메모가 말하는 "그림자 넣기"는 outline의 체감 표현으로 판단. 통일하려면 outline 제거 + 래퍼 '바탕색+그림자'만으로는 부족하고, **바 배경 하드코딩(752)을 조건부로 바꿔야** 접힌 블록(=바가 곧 블록 전체)에서 구분이 보인다. 이 변경은 접기 모드의 전체 색감(현재는 전 바가 활성색)을 바꾸므로 시각 검수 필수(R1).

**타당성: 상 (CSS·조건 분기 수준).**

## 3. 설계

### D1. 삭제 시 활성 승계 = 이웃 블록 (P1a)

`handleDeleteBlock`에서 삭제 블록의 인덱스를 구해, **삭제 자리를 이어받는 블록**(다음 블록, 마지막이었다면 이전 블록)을 활성 승계:

```ts
setCurrentBlocks((prev) => {
  if (prev.length <= 1) return prev;
  const idx = prev.findIndex((b) => b.id === blockId);
  const filtered = prev.filter((b) => b.id !== blockId);
  if (activeBlockId === blockId) {
    const next = filtered[Math.min(Math.max(idx, 0), filtered.length - 1)];
    skipNextBlockScrollRef.current = true;   // D2와 세트
    setActiveBlockId(next?.id || null);
  }
  return filtered;
});
```

### D2. 삭제로 인한 활성 전환은 자동 스크롤 no-op (P1b)

기존 `skipNextBlockScrollRef` 관례(1801 — handleSelectBlockBar 1936·찾기/바꾸기 2134 등과 동일 패턴)를 그대로 사용해 삭제 직후 1회 스크롤을 억제. 이웃 블록이 이미 화면상 삭제 위치에 있으므로 시각적 점프가 0이 된다. 별도 신규 상태 불요.

- StrictMode 이중 실행 주의: `setCurrentBlocks` updater 안에서 ref·setState를 부수효과로 건드리는 현행 구조(1548–1551도 동일)가 dev 이중 호출에 안전한지 CLI 확인(R4). 필요 시 updater 밖에서 idx 계산 후 순차 호출로 재구성.

### D3. 접힌 바에 '요약에 넣기' 스위치 + 삭제 버튼 (P2)

접힌 분기(780–790)의 미리보기 `<span>` 뒤에 우측 정렬로 추가:

```
[grip] [타입라벨] [첫 줄 미리보기 …(flex:1)] [요약에 넣기 ⊙] [🗑]
```

- `summaryToggle`(706–724)을 그대로 재사용(이미 stopPropagation 격리·비활성 노출 선례 `showSummaryOnlyBar` 있음).
- 삭제 버튼도 펼친 분기(823–838)와 동일 부품·동일 `canDelete` 가드. **접기 모드에선 비활성 블록도 삭제 가능**해지는 것이 이 변경의 본질 — `handleDeleteBlock`은 blockId 인자를 받으므로 추가 수정 불요. 비활성 블록 삭제 시 activeBlockId는 불변(D1 분기 미진입)이라 스크롤도 없음.
- 삭제된 블록이 선택집합에 있었다면 `selectedBlockIds`에서 제거(현행은 selection 정리를 안 함 — stale id는 무해하지만 위생상 함께 정리).
- 접힌 바 높이·밀도는 현행 유지. 미리보기 텍스트는 `minWidth:0` ellipsis라 버튼 공간 확보에 문제 없음(좁은 폭 실측 R2).
- 더블클릭(개별 펼침)과의 충돌: 버튼 위 더블클릭은 stopPropagation으로 바에 도달하지 않음 — 실측 확인 항목.

### D4. 접기 모드 바 클릭 스크롤 억제 (P3 전제)

`handleSelectBlockBar`에 collapseMode 가드를 추가해, 접기 모드에서는 활성화만 하고 **스크롤을 걸지 않는다**(Phase 45 "더블클릭 보호" 설계 의도 복원):

```ts
if (!collapseModeRef.current) {   // 접기 모드: 목록이 튀면 안 된다
  scrollEditorToBlockTop(blockId);
  scrollPreviewToBlockTop(blockId);
}
```

- `collapseMode`를 useCallback 의존성에 넣거나 ref 미러로 참조(현행 콜백들의 관례에 맞춰 CLI가 결정).
- 펼친 모드의 상단바 클릭 스크롤(Phase 56 동작)은 현행 유지.

### D5. 범위 선택 (P3)

- **앵커**: 마지막 일반 클릭(=활성화)된 블록. 접기 모드에서 일반 클릭 시 `selectionAnchorRef = blockId` 저장.
- **Shift+클릭**: 앵커~대상 사이의 연속 구간을 문서 순서로 **선택집합에 설정**(교체). 앵커가 없으면 대상 1개만 선택.
- **비연속 개별 토글**: Q2 확정 전까지 현행 Shift+클릭 토글을 **Alt(Option)+클릭**으로 이관하는 안을 기본안으로 둔다(Ctrl/Cmd는 Phase 45에서 브라우저 충돌로 폐기된 이력 승계 — macOS Ctrl+클릭=컨텍스트 메뉴, Cmd+클릭=링크 동작).
- 묶음 이동(`handleDragEnd`)은 무수정 — 선택집합만 바뀌고 이동 로직은 연속·비연속을 이미 처리한다.
- 발견성: 접기 모드 진입 시 1회성 힌트 또는 바 title 툴팁("Shift+클릭: 범위 선택 · Alt+클릭: 개별 선택")— 최소로 title만 권고.

### D6. 선택 표시 = 바탕색 + 그림자 통일 (P4)

| 요소 | 변경 |
|---|---|
| 래퍼(683–699) | `outline` 제거. `강조 = isActive \|\| selected`로 정의하고 `background: 강조 ? --block-bg-active : --block-bg`, `boxShadow: 강조 ? --block-shadow-active : none` |
| 바 배경(752) | 하드코딩 제거 → **펼친 바**: 현행 유지(`--block-bg-active`, 활성 헤더 문법). **접힌 바**: `transparent`로 두고 래퍼 배경이 비치게 함(접힌 블록은 바=블록 전체이므로 래퍼 문법이 곧 블록 문법이 된다) |

- 결과: 접기 모드에서 비선택 블록은 펼친 모드의 비활성 블록과 같은 `--block-bg`, 선택/활성 블록은 `--block-bg-active`+그림자 — 메모 요구("펼친 상태와 동일한 통일 문법")와 일치.
- 접기 모드의 활성(마지막 클릭) 블록과 선택집합 블록이 같은 표시가 되는데, 접기 모드의 목적(재배치)상 구분 불요로 판단 — Q3.
- 다크 모드 토큰(`--block-bg`/`--block-bg-active`/`--block-shadow-active`)은 기존 정의 재사용, 신규 토큰 없음.
- `showSummaryOnlyBar`(703)·제목 블록 돌출(§, 680)과의 시각 간섭 없는지 확인(R1).
