## 2. 확정 사실 (`origin/main f6513a0` — v2가 전건 재실측)

### F1 ✓ 새 질문이 덕수 목록에 들어가지 않는다

`lib/askQuestions.ts:100-124` `ensureSeeded`:
```
105:    const existing = await listAskQuestions(userId);
106:    if (existing.length > 0) return existing;      ← 비어 있을 때만 씨앗
```
덕수 컬렉션에는 G1~G3가 있으므로 `SEED_QUESTIONS`에 P1~P4를 더해도 **아무 일도 일어나지 않는다.**
호출부는 팝오버 열기(`AskListPopover.tsx:97` `setQuestions(await ensureSeeded(uid))`) 하나다.

단순히 "없는 씨앗을 채운다"로 바꾸면 반대 문제 — **덕수가 지운 질문이 다음 열기에 되살아난다.**
→ "어느 씨앗을 이미 제안했는가"를 기록해야 한다(D4).

### F2 ✓ 문제 질문의 범위 표시가 뒤집힌다

`CommentPanel.tsx:578-620` `buildContext(opts?: { solutionTarget?: boolean })`:
- `handleAskSend`(`:891-894`)가 **모든 문답 전송에 `solutionTarget: true`를 고정으로** 넘긴다 — 질문의 target을 보지 않는다.
- 절 제목(`:592-595`): `solution` 탭 → `### [풀이] — 검증 대상`, 그 밖 → `### [라벨] — 참고 자료 (검증 대상 아님)`
- 총괄 안내 `ASK_SCOPE_NOTE`(`:39-40`): "※ 검증·지적 대상은 [문제]와 "검증 대상" 표시가 붙은 탭뿐입니다…"

→ P2(표기·표현)를 보내면 모델은 **"풀이도 검증 대상"** 이라는 안내와 함께 받아 풀이의 표기까지 지적한다.

⚠ **v2가 추가로 확인한 것(S3)**: 총괄 안내는 `hasReference`가 참일 때만 붙는다(`:601-604`).
`hasReference`는 **`target && t.id !== 'solution'`인 탭이 실제로 내용을 가질 때만** 참이다(`:591-592`).
즉 **문제 탭 + 풀이 탭만 있는 흔한 문항에서는 안내가 아예 없고** 풀이 절에 `— 검증 대상`만 붙는다.
문제 질문에서는 풀이조차 참고이므로, **탭 내용이 하나라도 있으면 안내가 반드시 붙어야 한다.**

### F3 ✓ P1의 "풀이는 보지 말고"는 지켜질 수 없다

풀이가 컨텍스트에 실려 있으면 모델은 이미 읽었다. 읽은 풀이에 끌린 풀이는 **독립 풀이가 아니다.**

403-405:    parts.push('## 현재 풀이 (탭: …):' , body.currentTabContent)
```
→ 클라가 둘을 `undefined`로 보내면 **풀이 절 자체가 없다. 서버 변경 0.**

### F4 ✓ `$...$`도 백틱도 망가진다 — 실행으로 재현

주입 정규식 `EditorPreview.tsx:228-234`:
```js
result = result.replace(/(?<!\$)\$(?!\$)((?:[^$\\]|\\.)+)\$(?!\$)/g,
  (match, inner) => inner.trim().startsWith('\\displaystyle') ? match : `$\\displaystyle ${inner}$`);
```
보호 대상은 **코드펜스뿐**(`protectFences` `:81-88` — ` ``` ` 블록만). 인라인 코드는 보호되지 않는다.
같은 정규식을 그대로 이식해 돌린 결과:

| 문안 | `$` 개수 | 변형 | 말풍선 |
|---|---|---|---|
| `수식은 $...$로 감싸.` | 2 | **YES** | 수식 `…` |
| `` 수식은 `$...$`로 감싸. `` | 2 | **YES** | 코드 `$\displaystyle ...$` |
| `수식은 달러 기호($) 한 쌍으로 감싸.` | 1 | no | 글자 그대로 |
| **(꼬리 줄 삭제)** | **0** | **no** | — |

⚠ **66a 후속 턴의 "백틱으로 감싸라" 권고는 틀렸다** — 실행으로 확정.
⚠ AI가 받는 문장은 처음부터 멀쩡했다(전송은 전처리 전 원문). 대화 기록에서만 틀려 보인다.
⚠ 현행 씨앗 3개는 전부 `수식은 $...$로 감싸.`로 끝난다(`lib/ask/seed.ts:43·59·68`).

### P1 · 문제(성립) `seedKey P1` · `order 10` · **`withTabs false`**
```
문제만 보고 직접 풀어서 답을 구해줘. 첫 줄에 네가 구한 답을 적어줘.
그다음 이 문제가 성립하는지 봐줘:
- 조건을 만족하는 답이 없거나 둘 이상이면, 어느 조건이 부족하거나 서로 충돌하는지 짚어줘.
- 객관식이면 네 답이 선지에 있는지, 옳은 선지가 둘 이상은 아닌지, 선지끼리 형식(기약분수·유리화·단위)이 맞는지 봐줘.
- 수능형 단답이면 네 답이 1 이상 999 이하의 자연수인지 봐줘 — 아니면 문제나 조건이 잘못된 거야.
답을 확정하지 못했으면 어디서 막혔는지 적어줘. 문제에 없는 조건을 네가 보태서 넘기지 마 — 그 자리가 곧 지적이야.
```

### P2 · 문제(표기·표현) `seedKey P2` · `order 20` · `withTabs true`
```
문제 본문의 표기와 표현만 봐줘. 답이 맞는지는 보지 마. 사소한 것이라도 빠짐없이:
- 같은 문자가 서로 다른 뜻으로, 또는 다른 문자가 같은 뜻으로 쓰인 곳
- 수학 용어나 기호를 잘못 쓰거나 어색하게 쓴 곳 — 구간·집합·함수 표기, 첨자·괄호·로그 밑, 발문의 어투처럼 수능 문항의 관습과 어긋나는 것
- 두 가지로 읽힐 수 있는 문장, 무엇을 가리키는지 분명하지 않은 지시어, 오해를 부를 만한 표현
각 지적마다 원문을 짧게 인용하고, 어떻게 잘못 읽힐 수 있는지와 고친 문안을 적어줘.
지적이 많으면 답변 길이 제한보다 빠짐없이 적는 쪽을 우선해.
```

### P3 · 문제(과조건·군더더기) `seedKey P3` · `order 30` · `withTabs true`
```
문제의 조건 하나하나가 답을 구하는 데 실제로 쓰이는지 봐줘. 풀이가 있으면 각 조건이 풀이의
어느 지점에서 쓰였는지 짚고, 없으면 네가 풀면서 어디서 쓰는지 봐.
- 그 조건을 지워도 답이 그대로 하나로 정해지면 과조건이야.
- 다른 조건에 이미 담긴 내용을 되풀이하거나 의미가 일부 겹치는 조건, 같은 말을 두 번 하는 서술은 군더더기야.
사소한 것이라도 빠짐없이 찾고, 각각 지워도 되는 근거(지운 뒤에도 답이 유일한 이유)와 삭제 문안을 적어줘.
단, 답의 존재나 유일성을 보장하는 데 필요한 조건(자연수·양수·정의역·서로 다른 점 등)은 과조건이 아니야.
지적이 많으면 답변 길이 제한보다 빠짐없이 적는 쪽을 우선해.
```

### P4 · 문제(개선 재작성) `seedKey P4` · `order 40` · `withTabs true`
```
이 문제를 더 나은 문제로 다시 써 줘. 묻는 것과 풀이의 핵심 아이디어는 그대로 두고, 세 가지를 목표로:

   계수·조건의 수치를 조정하고, 기계적으로 반복되는 계산이 있으면 그 반복이 사라지게.
② 의미가 겹치는 조건을 하나로 합치거나 지워서 논리적으로 군더더기 없게.
③ 길고 장황한 수식·서술을 짧고 명료하게 — 읽는 시간과 부담을 줄여 수학적 본질에 집중하게.
오류나 모호한 표현이 보이면 그것도 함께 고쳐.
먼저 고쳐 쓴 문제 전문을 적고, 그 아래 바꾼 곳마다 "원문 → 수정안 → 이유"를 항목으로 정리해줘.
수치를 바꿨으면 고친 문제도 답이 하나로 정해지는지 봐 주고, 바뀐 답을 함께 적어줘.
