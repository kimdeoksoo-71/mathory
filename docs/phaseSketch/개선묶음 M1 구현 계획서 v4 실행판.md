## 0. v4에서 확정한 것 (실측 3건)

v3의 V1·V4~V7과 사실표(B-7·E-5·E-6·G-5·H-5)는 **전건 재확인**했다. 뒤집힌 것은 둘이다.

### W1 — V3(표 안 파이프)은 **처방이 반대였다**. 실측으로 규칙을 다시 세운다

프로젝트의 실제 파이프라인(`remark-parse` + `remark-math` + `remark-gfm`)으로 측정:

| 셀 내용 | 결과 |
|---|---|
| `\| $\|x\|$ \|` (**bare `\|`**) | **셀 4개로 쪼개짐** — 표도 수식도 파괴 |
| `\| $\\|x\\|$ \|` (`\|` 이스케이프) | 셀 2개 ✔ **그리고 수식 노드가 `\|`를 그대로 받는다**(‖ 정상 렌더) |
| `\| $\\\\|x\\\\|$ \|` (v3의 `\\\|` 처방) | **셀 4개로 쪼개짐** — 처방이 표를 깬다 |
| `\| $\Vert x\Vert$ \|` | 셀 2개 ✔ |

→ **규칙 정정(D14⁗)**: ❶ 이미 `\|`인 것은 **그대로 둔다**(건드릴 이유가 없다) ❷ 진짜 문제는
**bare `|`** 다 — 수식 **안**의 bare `|`는 `\vert`로(짝 판별 불필요·글리프 동일·`\left|`도 `\left\vert`로
유효), 수식 **밖**의 bare `|`는 `\|`로 이스케이프한다 ❸ `\\|`는 절대 만들지 않는다.

### W2 — V2(array 열지정)는 **검출 조건이 발동하지 않는다**

`/\\begin\{array\}\{[^}]*\}/`를 `\begin{array}{|p{2cm}|l|}`에 걸면 **`\begin{array}{|p{2cm}`까지 먹고**
`|l|}`만 남는다(실측). 즉 v3이 제안한 "제거 후 `\begin{array` 잔재면 실패"는 **잔재가 없어서 안 걸린다**
— 쓰레기 `|l|}`가 본문에 남은 채 분할된다.

→ **정정(D4″)**: preamble을 **중괄호 균형 스캔**으로 정확히 떼어낸다. 새 `lib/latexScan.ts`
(**import 0**)에 `readGroup(text, openIdx)`를 두고 `mathSplit`·`proofread`가 **함께 쓴다**
(사본 금지 — `tabular`의 `{spec}`도 같은 문제를 갖는다). 균형이 안 맞으면 **실패**.

### W3 — 문서 stale

CLAUDE.md의 "`PrintStyles.css`는 `EditorView.tsx:51`이 import" → 실제 **`:56`**. §8에서 함께 고친다.
